Overview

reporting/output.rs is an Application-layer edge connector that materializes report outputs by consuming report-finalization requests and producing report.json metadata, latest artifact listings, and optional timestamped archive copies. It provides the reporting subsystem’s shared filesystem boundary for callers such as report initialization and publish commands, while enforcing that all report artifacts remain inside the report’s reports/latest/<report-id> directory.

The module maintains two output layouts:

  • Latest outputs live under reports/latest/<report_id>.
  • Archived outputs, when requested, live under reports/archive/<UTC timestamp>/<report_id>.

It writes metadata with an RFC 3339 produced_at timestamp, but uses a filesystem-safe UTC timestamp (YYYY-MM-DDTHH-MM-SSZ) for archive directory names. Metadata artifact paths are normalized to forward slashes for portable serialized output.

finalize_report_outputs is the primary entry point for most reporting workflows. It validates and deduplicates the entrypoint artifact, adds report.json at the latest report root, then delegates persistence and optional archival to write_report_metadata_and_archive.

Public API

All items are pub(crate): they are available throughout the sc-compose crate but are not part of its external crate API.

Item Purpose
LATEST_ROOT_RELATIVE_PATH Relative root for current report outputs: reports/latest.
ARCHIVE_ROOT_RELATIVE_PATH Relative root for archived report snapshots: reports/archive.
ReportMetadata Serializable on-disk metadata schema written as report.json. Contains report identity, kind, status, production time, entrypoint, and artifact paths.
ReportOutputRequest Lower-level request for writing metadata and optionally copying a supplied list of latest artifacts into an archive. The caller supplies metadata_path.
FinalizeReportRequest Higher-level request for finalizing a report. The module derives the metadata path as <latest report root>/report.json.
MaterializedReport Serializable result describing the completed report: metadata path, latest artifacts, and any archived copies.
OutputError Error type for timestamp formatting, invalid paths, directory creation, copying, metadata writing, and JSON serialization failures. Implements Display and std::error::Error.
finalize_report_outputs Validates a completed report’s entrypoint and artifacts, ensures the entrypoint appears once, creates metadata, and optionally archives all outputs.
write_report_metadata_and_archive Lower-level materialization function that writes metadata and copies artifacts into the archive tree when archive is enabled.

MaterializedReport serializes paths through crate::path_utils helpers. Its latest_artifacts field is emitted as JSON key artifacts; archived_artifacts retains its Rust field name.

Dependencies

  • std::fs operations create parent directories, write metadata, and copy artifacts.
  • std::path::{Path, PathBuf} represents paths relative to the supplied workspace root.
  • serde derives serialization and deserialization for metadata and serializes materialization results.
  • serde_json encodes ReportMetadata as pretty-printed JSON.
  • time supplies UTC timestamps and formatting:
  • Rfc3339 for metadata’s produced_at.
  • A custom format description for archive directory names.
  • crate::path_utils::to_forward_slash normalizes serialized metadata paths.

Important relationships:

  • reporting/init.rs calls write_report_metadata_and_archive when emitting smoke-report outputs.
  • commands/reports/publish.rs is a cross-layer consumer, making this module an Application-layer boundary used by command handling.
  • reporting/publish_manifest.rs relies on the same latest/archive root conventions when locating report material.
  • reporting/templates.rs, scaffolding, specification, and indexing code consume the report-output types or directory layout exposed here.

Usage Notes

Use finalize_report_outputs when the report artifacts have already been generated beneath the current report directory:

let result = finalize_report_outputs(
    workspace_root,
    &FinalizeReportRequest {
        report_id: "weekly-summary".to_owned(),
        kind: "summary".to_owned(),
        status: "success".to_owned(),
        entrypoint: PathBuf::from("reports/latest/weekly-summary/index.html"),
        artifacts: vec![
            PathBuf::from("reports/latest/weekly-summary/index.html"),
            PathBuf::from("reports/latest/weekly-summary/data.json"),
        ],
        archive: true,
    },
)?;

This performs the following sequence:

  1. Confirms the entrypoint is below reports/latest/weekly-summary.
  2. Starts the latest artifact list with the entrypoint.
  3. Adds other artifacts only if they are under the same report root; a duplicate entrypoint is skipped.
  4. Writes reports/latest/weekly-summary/report.json.
  5. If archiving is enabled, copies every latest artifact plus report.json into a single timestamped archive directory.
  6. Returns a MaterializedReport with both latest and archived relative paths.

Use write_report_metadata_and_archive only when a caller needs to control the metadata destination explicitly. Its latest_artifacts list must still consist of paths under the report root inferred from entrypoint; its metadata_path is also archived and must satisfy that same containment rule.

Path validation is intentionally lexical:

  • entrypoint.starts_with(reports/latest/<report_id>) must be true.
  • Every additional artifact must have the same prefix.
  • Archive copy destinations are derived by stripping that latest report root and appending the relative suffix below the archive root.

As a result, callers should provide clean, workspace-relative paths. Absolute paths, artifacts from another report ID, and paths outside reports/latest/<report_id> produce OutputError::InvalidPath. The module does not canonicalize paths or resolve symlinks, so callers should avoid relying on .. segments or symlink traversal for containment semantics.

Metadata is written before archival begins. If archival fails after metadata has been written, the filesystem may contain a valid latest report and a partially copied archive; MaterializedReport is not returned in that case. Similarly, copies are ordinary std::fs::copy operations: existing archive files may be overwritten if the same timestamped destination is reused.

Archive labels have second-level UTC precision. Two writes for the same report within the same second target the same archive directory, so the later operation can overwrite files with matching relative names. Callers requiring immutable or collision-free archives need coordination above this module.

ReportMetadata.artifacts includes all latest artifacts plus the metadata file itself. MaterializedReport.latest_artifacts follows the same convention, while archived_artifacts is empty when archive is false.
