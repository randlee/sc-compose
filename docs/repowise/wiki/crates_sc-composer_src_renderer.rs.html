Overview

renderer.rs is the Application-layer template rendering adapter that consumes template text, serializable context, and optional named supporting templates to produce rendered text or a RenderedArtifact.

It wraps MiniJinja behind the crate’s RenderError type and keeps composition entry points independent of direct template-engine APIs. Renderer owns a reusable minijinja::Environment, while the free functions provide one-shot and pre-loaded-template workflows.

The module configures every environment with trim_blocks and lstrip_blocks, making whitespace normalization consistent across standard rendering, custom-delimiter rendering, and pre-loaded rendering. Named rendering preserves template identities for diagnostics and enables template references to be resolved by name.

render_loaded_template is deliberately scoped to rendering already-discovered content: callers such as the composer remain responsible for filesystem discovery and repository traversal, while this module registers the supplied main and supporting templates and renders the requested named template.

Public API

Item Purpose
NamedTemplateAsset A named supporting template with template_name and template_text; used for {% include %} and {% extends %} resolution.
LoadedTemplateRequest Input for rendering pre-loaded content: main template identity/text, a BTreeMap<String, Value> context, and optional supporting templates.
RenderedArtifact Result of render_loaded_template, containing the rendered text and the rendered template’s stable name.
Renderer::new() Creates a renderer with the default MiniJinja environment and whitespace settings.
Renderer::with_delimiters(open, close) Creates a renderer using custom variable delimiters, returning RenderError if MiniJinja rejects the syntax.
Renderer::render(template, context) Renders inline template text under the synthetic name "inline".
Renderer::render_named(template_name, template, context) Renders one template string under an explicit name, improving error attribution and template identity.
render_template(template, context) Stable one-shot convenience API; creates a default Renderer and invokes render.
render_loaded_template(request) Registers caller-provided supporting templates and the main template, then renders the main template by name.

Renderer::with_options and Renderer::try_with_options are crate-private construction hooks. They allow internal callers to configure MiniJinja while centralizing the default whitespace behavior; the fallible variant is required for configuration operations, such as syntax installation, that MiniJinja can reject.

All render paths convert MiniJinja parsing, lookup, and execution failures into RenderError::render(...).

Dependencies

  • minijinja::Environment provides parsing, template registration, named-template lookup, syntax configuration, and rendering.
  • serde::Serialize lets Renderer::render, Renderer::render_named, and render_template accept arbitrary serializable contexts.
  • serde_json::Value and BTreeMap<String, Value> define the concrete, deterministic context shape used by LoadedTemplateRequest.
  • crate::RenderError is the module’s error boundary, preventing MiniJinja errors from leaking through the public composer API.
  • composer.rs uses Renderer::new and Renderer::with_delimiters during composition, so CLI-validated delimiter choices flow into the rendering environment.
  • lib.rs, the CLI, tests, and Python bindings expose or consume the rendering APIs without needing to instantiate MiniJinja directly.

Usage Notes

For a simple one-off render, use render_template:

use sc_composer::render_template;
use serde_json::json;

let rendered = render_template(
    "Hello {{ name }}!",
    json!({ "name": "Ada" }),
)?;

assert_eq!(rendered, "Hello Ada!");

For repeated independent renders using the same environment configuration, retain a Renderer:

use sc_composer::Renderer;
use serde_json::json;

let renderer = Renderer::new();

let greeting = renderer.render("Hello {{ name }}", json!({ "name": "Ada" }))?;
let farewell = renderer.render("Bye {{ name }}", json!({ "name": "Ada" }))?;

Use render_named when template identity matters for diagnostics or when matching an externally meaningful template name:

let output = renderer.render_named(
    "reports/summary.html.j2",
    "<h1>{{ title }}</h1>",
    serde_json::json!({ "title": "Status" }),
)?;

To support inheritance or inclusion, register every dependency in supporting_templates and ensure names match the paths referenced from the main template:

use std::collections::BTreeMap;
use sc_composer::{
    render_loaded_template, LoadedTemplateRequest, NamedTemplateAsset,
};
use serde_json::{json, Value};

let context: BTreeMap<String, Value> = json!({ "title": "Monthly report" })
    .as_object()
    .unwrap()
    .clone()
    .into_iter()
    .collect();

let artifact = render_loaded_template(LoadedTemplateRequest {
    template_name: "reports/monthly.html.j2".to_owned(),
    template_text: r#"
        {% extends "shared/base.html.j2" %}
        {% block body %}{{ title }}{% endblock %}
    "#.to_owned(),
    context,
    supporting_templates: vec![NamedTemplateAsset {
        template_name: "shared/base.html.j2".to_owned(),
        template_text: "<main>{% block body %}{% endblock %}</main>".to_owned(),
    }],
})?;

assert_eq!(artifact.template_name, "reports/monthly.html.j2");

Important behavior and pitfalls:

  • supporting_templates are parsed when registered. A malformed partial, base template, or include target fails before the main template is rendered.
  • Template references must use the same names supplied in NamedTemplateAsset; this module does not resolve filesystem paths or infer aliases.
  • render always uses the name "inline". Use render_named when errors need to identify a specific source template.
  • Whitespace is intentionally normalized: block-only lines are trimmed and leading indentation before block tags is stripped. MiniJinja’s {%+ ... %} modifier can opt out of left-stripping where preserved indentation is required.
  • with_delimiters changes variable delimiters only. It does not alter block or comment delimiters.
  • Custom delimiters are validated by MiniJinja; invalid tokens return a typed RenderError instead of panicking.
  • render_loaded_template accepts a JSON-object-shaped context rather than a generic Serialize value, which makes the pre-loaded boundary straightforward for callers such as bindings and orchestration code.
