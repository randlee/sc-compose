Layer: Test

I’ll trace the listed tests and their application-facing seams so the overview reflects the repository’s actual verification architecture.

Overview

The Test layer is the verification layer that exercises the application-facing CLI, composition library, Python bindings, experimental multipass prototype, and generated test evidence. It protects observable contracts: rendered output, validation and resolution failures, exit codes, JSON schemas, report artifacts, cross-platform path handling, and the repository’s standalone boundary.

Key Components

  • crates/sc-compose/tests/cli.rs runs the compiled sc-compose executable against isolated temporary workspaces. It covers rendering, validation, verification, template initialization, variable-file parsing, multi-pass rendering, examples, template packs, and report lifecycle commands.
  • crates/sc-compose/tests/json_cli.rs verifies the machine-readable CLI contract. It checks the versioned { schema_version, payload, diagnostics } envelope, clean stdout in JSON mode, diagnostic codes, dry-run payloads, and reporting command responses.
  • crates/sc-compose/tests/support/mod.rs provides reusable fixture construction, temporary roots and logs, command invocation, JSON parsing, path normalization, and report/template fixture helpers.
  • crates/sc-compose/tests/repo_boundaries.rs is an architectural guardrail. It recursively scans Rust sources and manifests to reject ATM environment references, ATM or agent-team-mail imports, and prohibited dependency families.
  • crates/sc-composer/tests/integration.rs calls the pure sc-composer API directly. It validates multi-pass parsing/rendering, defaults, context/pass mismatches, higher-brace preservation, backward compatibility, and observer event sequences.
  • bindings/python/tests/test_smoke.py validates the Python extension’s public surface: exported types, informative representations, composition, validation, resolution, rendering, include expansion, initialization, diagnostics, and multi-pass access.
  • prototype/multipass/test_integration.py and test_multipass.py test the separate Python prototype’s parser, token discovery, staged renderer, template conversion, verification, and single-pass compatibility behavior.
  • reports/inputs/test/matrix.md and results.md are report-source inputs that describe compatibility coverage and workspace-test evidence for the reporting pipeline.

CLI tests inject templates, variables, catalogs, and expected files into fresh directories, invoke the binary, then inspect process status and produced artifacts. JSON tests parse stdout into structured values and assert envelope and diagnostic stability. Library tests supply ComposeRequest values directly and capture observer events. Binding tests make the same capabilities available through Python objects. Report inputs flow into the reporting subsystem as publishable evidence about these checks.

Architecture Notes

The Test layer depends outward on the Application layer: it invokes the sc-compose binary and imports the sc-composer library APIs, but production code does not depend on tests.

The layer intentionally verifies behavior at several boundaries rather than duplicating unit coverage. CLI tests own process-level concerns such as flags, exit codes, filesystem writes, and JSON output; library integration tests own public composition semantics and observability; Python tests own binding completeness and type conversion.

Fixtures are deliberately filesystem-backed and temporary, which makes path confinement, include behavior, report generation, dry-run semantics, and normalization observable without mutating repository content. The shared support module also normalizes Windows extended-path prefixes and separators to keep assertions portable.

repo_boundaries.rs is a policy test as well as a functional test: it enforces that this standalone toolchain remains independent of the ATM runtime and its dependency family. The multipass tests document and validate a prototype path; they should be treated separately from the Rust production-contract suites.
