# Sprint G.6 — Adversarial Evidence and Hardening

## Goal

Run a bounded, reproducible multi-agent campaign against the complete Phase-G
extraction surface. Each worker generates one focused class of realistic
template/rendered-output cases and returns structured results. The coordinator
minimizes and replays failures, traces confirmed findings to a requirement or
ADR when one exists, recommends a new requirement or ADR only for a genuine
contract gap, and promotes confirmed regressions into the owning test suite.

## Hard dependencies

- G.1 through G.5 are merged into the campaign baseline.
- `.claude/skills/adversarial-fuzzing/` is the authoritative worker and report
  protocol; this sprint supplies the Phase-G target and evidence artifact.
- The campaign must exercise Rust, Python, and CLI surfaces without allowing
  research-only extraction artifacts to become a production dependency.

## Exact targets

- `docs/phase-G/evidence/g-6-reverse-extract-campaign.json`
- `crates/sc-composer/src/extract/tests.rs`
- `crates/sc-composer/tests/extract_integration.rs`
- `crates/sc-compose/tests/cli/extract.rs`
- `crates/sc-compose/tests/json_cli/extract.rs`
- `bindings/python/tests/test_smoke.py`
- `docs/requirements.md` and `docs/architecture.md` only when a confirmed
  finding demonstrates a missing or inaccurate contract
- `.claude/skills/adversarial-fuzzing/` only when the shared protocol itself
  cannot represent the required evidence

## Campaign contract

The primary agent launches at most four workers with fixed seed `7001`:

- `shape-probe` — repeated siblings, attributes, text nodes, whitespace,
  entities, declarations, and comments;
- `template-probe` — supported scalar expressions versus unsupported filters,
  control flow, concatenation, and type-looking values;
- `boundary-probe` — malformed XML, missing occurrences, ambiguity, empty
  values, and include/exclude selection;
- `differential-probe` — compare Rust, Python, and CLI results for the same
  known-template case.

Each worker has at most 50 cases and 120 seconds. A worker returns structured
JSON even when it finds no issue or cannot complete. A missing or malformed
worker result is itself recorded as an inconclusive finding; it is never
silently counted as a pass.

## Deliverables

- `G6-D1` — Execute the fixed-seed campaign with the worker limits above and
  record worker status, case counts, and tool versions.
- `G6-D2` — Record every candidate with the template, rendered input, expected
  relation or requirement, observed output, and minimized reproduction. The
  HTML report is generated by the shared adversarial-fuzzing skill; this JSON
  is its machine-readable Phase-G evidence source.
- `G6-D3` — Replay each candidate at least three times and classify it as
  confirmed defect, intentional documented boundary, or inconclusive.
- `G6-D4` — For confirmed defects, identify the governing requirement/ADR or
  document the evidence-backed contract gap and proposed requirement/ADR.
  Do not create an ADR merely to record an implementation detail.
- `G6-D5` — Promote every confirmed regression into the smallest owning Rust,
  Python, or CLI test, with a regression test that includes the triggering
  template and rendered input.
- `G6-D6` — Re-run the complete validation gates and publish the evidence
  artifact with unresolved owners and next actions explicitly listed.

## Evidence schema

The committed JSON must contain at least:

```json
{
  "phase": "G",
  "sprint": "G.6",
  "baseline": "<commit>",
  "seed": 7001,
  "limits": {"max_workers": 4, "cases_per_worker": 50, "timeout_seconds": 120},
  "workers": [],
  "findings": [],
  "promoted_tests": [],
  "summary": {
    "workers_passed": 0,
    "workers_failed": 0,
    "confirmed_defects": 0,
    "intentional_boundaries": 0,
    "inconclusive": 0
  }
}
```

Finding records must preserve enough information for a reviewer to decide
whether the case is a realistic customer use case: description, template,
rendered input, expected behavior, observed behavior, classification, replay
count, requirement/ADR trace, and recommended change.

## This sprint does not close

- new output formats, unknown-template identification, loop reconstruction, or
  typed-value inference;
- unsupported behavior being silently changed to pass a generated case;
- a no-finding claim when a worker failed, timed out, or returned invalid JSON;
- broad refactoring unrelated to a confirmed Phase-G finding.

## Acceptance criteria

- All workers return valid structured results or have explicit failed-worker
  records in the evidence.
- Every candidate has a concrete template and rendered input, a classification,
  and a reproducible replay result.
- Confirmed defects are traced to requirements/ADRs or have an evidence-backed
  contract-gap recommendation, and are promoted to regression tests.
- Rust, Python, and CLI behavior is compared for differential cases, with
  intentional differences documented.
- The evidence artifact is reviewable without reconstructing the campaign from
  agent logs.
