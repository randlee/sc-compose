boundary-001

Minimal template / frontmatter
UTF-8 bytes EF BB BF followed by ---\nvariables:\n name:\n required: false\n---\nHello {{name}}\n
Input
name=x
Expected
UTF-8 BOM is accepted before frontmatter; output contains only the rendered body
Observed
exit 0; stdout includes the complete frontmatter block before Hello x
Requirement / ADR
No requirement or ADR currently covers this BOM-frontmatter behavior; the E.3 evidence records the parser boundary oracle.
Requirement / ADR follow-up
Assess whether BOM-prefixed frontmatter is a supported user contract. If yes, create or update the requirement/ADR before implementing the parser fix; if no, document the intentional boundary rather than creating a needless ADR.
Root cause
The file-frontmatter path does not strip the leading UTF-8 BOM before detecting the frontmatter delimiter.
Recommended fix
Add a CLI regression test, then normalize a leading UTF-8 BOM if the product decision accepts it.

boundary-002

Minimal template / frontmatter
---\n---\nbad \xff\xfe bytes\n
Input
invalid UTF-8 bytes ff fe in the template body
Expected
nonzero exit with a template/config UTF-8 diagnostic
Observed
exit 2 with ERR_INCLUDE_NOT_FOUND naming the template itself
Requirement / ADR
No requirement or ADR currently covers the exact invalid-UTF-8 diagnostic wording.
Requirement / ADR follow-up
Confirm the supported diagnostic boundary; create or update documentation only if stable UTF-8 diagnostics are a supported contract.
Root cause
The invalid-byte path is classified by include resolution before template decoding.
Recommended fix
Add a regression test and align error classification with the documented boundary.

boundary-003

Minimal template / frontmatter
---\nvariables:\n needed:\n required: true\n---\nX {{needed}}\n
Input
no value supplied for needed
Expected
missing declared required variable reports ERR_VAL_MISSING_REQUIRED
Observed
exit 2 with ERR_VAL_UNDECLARED_TOKEN for needed
Requirement / ADR
The required-variable diagnostic contract needs reconciliation in existing documents.
Requirement / ADR follow-up
Update an existing requirement/ADR if one defines the behavior; create a new one only for a genuine supported-contract gap.
Root cause
Required-variable metadata is not applied before undeclared-token validation.
Recommended fix
Reconcile validation ordering and add a CLI regression test.
