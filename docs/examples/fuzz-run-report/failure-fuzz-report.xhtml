A BOM-prefixed frontmatter template reproduced a stable output leak across three runs.

Expected versus observed

Expected
UTF-8 BOM is accepted before frontmatter; output contains only the rendered body.
Observed
exit 0; stdout includes the complete frontmatter block before Hello x.

Requirement / ADR trace

No requirement or ADR currently covers this BOM-frontmatter behavior; the campaign applied the parser boundary oracle recorded in the E.3 evidence.

Requirement / ADR follow-up

Assess whether BOM-prefixed frontmatter is a supported user contract. If yes, create or update the requirement/ADR before implementing the parser fix; if no, document the intentional boundary rather than creating a needless ADR.

Root-cause analysis

The file-frontmatter path does not strip the leading UTF-8 BOM before detecting the frontmatter delimiter, so the delimiter is rendered as ordinary template content.

Recommended fix

Add a CLI regression test for BOM-prefixed frontmatter parsing, then implement the requirement/ADR decision above and normalize a leading UTF-8 BOM if the behavior is supported.
