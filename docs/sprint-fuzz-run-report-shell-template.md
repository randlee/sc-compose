# Sprint — Top-Level Report Shell Template

## Goal

Today only the per-worker panel has a checked-in Jinja2 template
(`.claude/skills/html-report/templates/fuzz-run-agent.xhtml.j2`). The
top-level report shell (header, session-summary table, composed worker
sections, footer, metadata table) is hand-assembled by the
`.claude/agents/html-report-generator.md` background agent directly from
prose instructions, with no checked-in shell template behind it. The
repo-owned `.claude/skills/html-report/fuzz-run-agent-contract.md` already
requires deterministic `sc-compose` rendering — the shell currently does
not follow that.

This sprint adds a second template that owns the top-level shell, so the full
report — not just the worker panel — is deterministically generated by
`sc-compose render` from a JSON var-file, with zero hand-assembled or
ad-hoc-generated markup.

## Variable Contract

New template: `.claude/skills/html-report/templates/fuzz-run-report.html.j2`

Confirmed via direct testing against the installed `sc-compose` CLI
(`v1.2.0`) that both shapes below render cleanly through
`sc-compose render --var-file` today — no product bug blocks this contract:

- `rows`: **top-level** array of objects, one per fuzz-run row in the
  session-summary table, e.g.
  `{"label": "...", "iterations": 99, "pass": "99/99", "result": "PASS"}`.
  (Top-level array-of-objects has shipped since PR #50 / FR-13.)
- `sections`: **top-level** array of strings — each string is one worker
  panel's already-rendered XHTML (the output of rendering
  `fuzz-run-agent.xhtml.j2` once per worker), inserted verbatim into the
  shell. This keeps `sections` a flat array of scalars, not an array of
  objects or nested arrays, so it is unaffected by the still-open nested-path
  array-of-objects gap (tracked separately, see Non-Goals).

Required top-level scalar variables (mirroring
`.claude/skills/html-report/fuzz-run-agent-contract.md`'s input contract
naming where it overlaps): `title`, `subtitle`, `generated_at`, `status`, `summary_intro_html`
(the prose paragraph(s) above the table), `rows`, `sections`,
`recommendations_html` (optional), `footer_html` (optional), and a
`metadata_rows` top-level array of objects (same shape rule as `rows`) for
the closing metadata table.

## Non-Goals

  limitation (`agent.test_inputs` and similar) — that gap is tracked
  separately and is not required for this contract, since `rows`,
  `sections`, and `metadata_rows` are all top-level arrays.
- Do not change the worker-panel template's markup or variable contract
  beyond what already landed in commit `4910eca` on this branch.
- Do not touch `20260729-1-fuzz-report.*` or `20260729-2-fuzz-report.*` in
  this sprint — regenerate only `20260729-3-fuzz-report.*` as the proof case.
- Do not build a website index page.

## Completion Evidence

The shell template rendered successfully from a generated var-file containing
four top-level `rows` objects, four top-level `sections` strings, and eleven
top-level `metadata_rows` objects. The exact proof command completed with exit
code 0:

```bash
target/debug/sc-compose render --root . \
  --file .claude/skills/html-report/templates/fuzz-run-report.html.j2 \
  --var-file /tmp/sc-compose-fuzz-run-shell-vars.json \
  --output site/reports/20260729-3-fuzz-report.html
```

The in-repo generator guidance is delivered by
`.claude/agents/html-report-generator.md`, registered in
`.claude/agents/registry.yaml`. The in-repo two-template and top-level-array
guidance is documented in `.claude/skills/html-report/fuzz-run-agent-contract.md`.

The var-file was derived from
`site/reports/20260729-3-fuzz-report/20260729-3-fuzz-report.json` and the
existing four worker panel artifacts. No worker panel or JSON sidecar was
rewritten. The only generated report artifact touched by this sprint was
`site/reports/20260729-3-fuzz-report.html`, and it was produced by the
`sc-compose render` command above rather than hand-edited.
