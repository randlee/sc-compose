## Acceptance criteria

FR-24 behavior passes through real Rust/CLI/Python adapters with equivalent rendered values and bd commands. Direct-input refusal cases are explicit: a duplicate --var key, mixed --request/direct input, an unresolved formula, and a missing required variable each fail with the documented request/validation outcome and create no bead or edge. The direct plan-fix command and JSON path have matching stored results. Optional-node/edge false/true branches, false-to-true additions and true-to-false state preservation work. Existing-owned missing and newly declared edges are created without manual commands; conflicts/foreign ownership and dangling references fail before mutation. Controlled apply failure rolls back all additions and ambiguous completion is reconciled safely. Existing status/notes/assignee survive. Legacy bd-owned cases retain their exact bytes/codes/argv. A verified v1 creation snapshot/history can migrate provenance and add elements atomically without changing user fields; missing migration proof refuses safely. Each named historical case has an honest mapped result or a declared missing-input blocker.

With --render-by bd, sc-compose keeps passing registry variables to bd as --var arguments; graph pour by path rejects caller bead inputs with BEADS_GRAPH_FORMULA_UNSUPPORTED (reason bead_variables_set); and attach rejects them with attach forbids bead_variables, all exactly as v1.7.0.
