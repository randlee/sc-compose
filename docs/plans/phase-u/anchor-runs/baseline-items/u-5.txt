# u-5: managed-kit-adoption

## Description

### Released managed tooling and supported consumer checks
### Deliverables
1. Install actual released sc-lint0.8.5 native/wheel/kit via its supported dry-run/apply flow, preserving approved U2 strict policy, packaged pytests, PATH/cross fixes, logging/artifacts and real exit/envelope semantics. Verify actual artifacts, not assumed future support.
2. Upgrade sc-publish through its supported installer; PR847 is open and QA-passed per lead. Reuse that change, do not recreate it or hand-edit vendored kit files. Retain prerelease/archive supported flows and offline CLI payload support.
3. Declare existing consumer preflight_checks id/description/run entries for scripts/check_render_regressions.py and scripts/check_install_matrix.py. The first reuses U2 current-only byte command. The second verifies successful workflow_dispatch integration evidence for the candidate/artifact identities using ordinary run metadata; missing/stale/failed evidence fails. No new shared evidence schema/service or kit-specific consumer logic. U8 supplies real matrix evidence; U9 proves integrated positive/negative behavior.
4. Enable sc-docli through the kit's existing docli config; every publish runs it and stale generated CLI docs block preflight. External executable only, no sc-docli crate dependency. U6 supplies actual Clap model/generated content; U9 verifies installed offline delivery.
5. Preserve actual policy and exit/report behavior. Kit/config/helper tests prove pass/finding/config/large-finding normalization without dropping stderr or confusing analyzer exit10 with success. No publication in this sprint.
Matrix verifier contract: before publication, scripts/check_install_matrix.py computes SHA-256 from every exact release artifact selected by the existing release/build manifest and compares its artifact identity and digest to the successful U8 workflow run. Obtain U8 run metadata and per-artifact digests from that run’s existing workflow artifact outputs; resolve the expected workflow/repository/candidate and successful run through ordinary GitHub run metadata, not consumer-supplied success flags. Reject missing, extra/uncovered, stale, failed, wrong-candidate or mismatched artifact identities/digests, including changed bytes from the same candidate. No shared kit schema is introduced.
Release sequencing owner (CONSISTENCY-001): U5 verifies the canonical sc-publish capability, routes any missing capability to the sc-publish owner, and adopts it through the supported immutable upstream package, not patch vendored workflows. PR847 reuse alone is insufficient unless it provides this behavior. The consumer release workflow selects the successful U8 workflow run for the exact candidate and intended release version, downloads its already-built release files, and runs existing preflight_checks on those files before gate-and-tag. gate-and-tag must preserve that candidate/tree and artifact versions. Publisher jobs then consume those same retained files, rechecking SHA-256 immediately before upload; remove the current post-gate rebuild path for these artifacts. No rebuild, version rewrite, fallback build, or substitution may inherit old matrix evidence. Changed candidate/version/bytes requires a new build and matrix run. U5 implements this supported input/staging path and deterministic negative tests using fixtures; U8 provides real files and U9 owns actual producer-to-publisher rehearsal. A missing upstream capability is an owned U5 deliverable/blocker, never assumed present or a local fork.
Missing upstream release capability remains a U5 adoption blocker: coordinate the change with its canonical owner and verify the released supported installer; consumer U5 never claims ownership of an upstream fork or patches copied assets.

## Acceptance criteria

cargo test --workspace, targeted adapter/tooling tests and supported kit dry-run convergence pass. sc-lint actual0.8.5 strict outcomes/true counts, pytests and raw exits are preserved. Kit consumer config uses existing id/description/run and docli interfaces; script negative cases fail for absent/wrong-candidate matrix evidence and unlisted byte differences, stale CLI reference blocks preflight. Full real producer/consumer acceptance is U9 after U8, not a fixture-only U5 closure of matrix delivery. No publishing. Targeted deterministic verifier tests include identical-candidate wrong-SHA-256, missing digest/artifact, uncovered release artifact and matching exact-byte success; digests are computed from the selected files, not trusted filenames. Supported kit installation demonstrably routes release publisher jobs to retained tested files instead of post-gate rebuilds; selection/version/hash failures stop before gate/tag and any last-mile digest mismatch stops before upload. Fixture tests prove the path; actual U8-backed end-to-end closure belongs to U9.
