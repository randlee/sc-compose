# u-8: wheel-install-validation

## Description

### Complete delivery matrix and preflight-required integration test
### Deliverables
1. Consume U5 final kit/build-manifest contract and U7 all-three abi3-py311 implementation. Complete release/publish-artifacts.toml and templates, Go native-module target packaging/helpers and applicable channel configuration for macOS/Windows/Linux x x64/arm64 across Rust CLI,3wheels and sc-sha-go. Build actual artifacts, preserve Go consumer ZIP verification and Rust/offline payloads. No platform is optional because the old1.7.0 matrix omitted it.
2. Provide workflow_dispatch-only full integration workflow. Windows x64/arm64 run on GitHub, not unavailable local hardware; Linux arm64 may use isolated Colima/native hosted runner. Test the declared CPython3.11/3.12/3.13/3.14 matrix on all6 platforms with all3 wheels and both pip/uv; test actual Rust CLI and external Go module installs through applicable delivery channels. Product metadata>=3.11 has no upper bound; tested minors are an explicit coverage list, not a maximum supported version.
3. Run against workflow-built candidate artifacts with actual hashes/versions and stored-value/import/readback outcomes. Wrong ABI/tag/runtime metadata and loader failures are real findings. Archive normal stdout/stderr, per-cell step.json and one aggregate plus run links. Missing cells never PASS. U5 scripts/check_install_matrix.py consumes ordinary successful workflow evidence for preflight; U9 verifies that integration.
4. Normal sprint/PR CI never runs this full matrix or rebuilds wheels. Retain the small cached Linux ABI3 wheel consumption path (floor/current declared test interpreter, pip+uv) plus U2 fast byte check; U9 wires it once. Private-index install rehearsal uploads nowhere and removes owned services/environments after evidence capture.
5. This is required integration evidence before publish, superseding the old procedure-only rule; it is not a new certificate framework or new workflow per sprint. Phase U itself does not publish.
Artifact evidence handoff to U5/U9: hash every exact workflow-built release file with SHA-256, preserve its existing release-manifest identity/path and candidate/run association in ordinary workflow artifact outputs, and make those exact files available to the publication preflight verifier. The matrix must install those same files; no post-test rebuild may reuse their passing evidence. Cover all artifacts selected for publication, including non-wheel artifacts. U5 owns the consumer comparison contract; U9 proves the real producer-to-consumer path.
Apply accepted ADR-0022: binding target facts belong to the consumer; Go-native helper/schema/tests belong to the canonical peer package. Any needed helper capability is delivered through that upstream package and its supported installer, with byte-identical immutable assets/provenance. Do not patch vendored helpers locally, add Go-native commands to the core release helper, or extend the closed core manifest with a go_native table.
Release input handoff: build once for the intended publication version before gate/tag, run the full matrix on those immutable files, and retain them with the successful run identity for U5 release-workflow selection. Do not rebuild for the final tag or rewrite versions. Any candidate/version/content change invalidates the run for publication and requires a fresh matrix. U9 proves the supported publisher consumes this run’s exact retained files; Phase U rehearses without public uploads.
Explicit Go contract owner: update bindings/sc-sha-go/native/targets.toml from its current3 targets to all6 required targets and prove archive/loader/cgo selection on each. An infeasible target is a visible release blocker, never a dropped cell. U8 installs the canonical peer package from pinned immutable provenance through release/go-native-module-install.json and plugins/go-native-module/**; release/go-native-module.toml and publish manifests are installer-rendered outputs only. Vendored .github/scripts helpers are never hand-edited; needed helper changes route upstream and arrive through supported installation.
U8 owns ADR-0022 verify-version-lockstep wiring after the core check in CI, preflight, release and release-gate paths, using supported kit/peer installation and consumer configuration, not local helper patches. U5 supplies the installed kit contract; U9 verifies these four real invocation paths. U8-time matrix evidence covers only its candidate. Publication must dispatch a new full workflow_dispatch run on the final post-U10-U13 publication candidate/version and retain/test/publish its exact artifacts under FR-25.4; no earlier upgrade run is reused for changed code.
Approved artifact/channel map deliverable (ANC-022): make the assigned channels explicit for each of the five required artifact families and its applicable platform cells. Maintain the reviewed consumer map through release/sc-publish-install.json and its supported rendered release/publish-artifacts.toml, with the separate Go peer contract and release workflow supplying Go ZIP/module assignments. release/publish-channel-contracts.toml supplies channel protocols, not artifact applicability. Do not assume the install JSON alone lists every artifact/channel pair or put Go-native fields into the closed core schema. Verify all assigned channels are accounted for against actual delivery; preserve the separate FR-25.1 obligation that all30 artifact/platform cells build successfully.

## Acceptance criteria

cargo test --workspace plus matrix-runner/helper tests pass. Actual6x5 artifact/platform support and applicable channels are complete; declared Python>=3.11 ABI tags/imports and every planned install cell has an actual result. Full integration trigger is workflow_dispatch only; missing/failed/wrong-head evidence fails preflight through the existing consumer check. Normal CI stays the small cached install path+fast byte check. Real loader/platform gaps remain findings, never generated-success rows. Owned disposable environments are cleaned; required evidence survives publication preflight. Each tested artifact has a retained SHA-256 and release identity in its successful run outputs, and the exact bytes selected for publication can be matched by the U5 verifier; missing or changed bytes cannot inherit a passing matrix result. An explicit reviewed per-artifact channel map covers Rust CLI, all three wheels and Go native-module delivery using the existing consumer and Go peer contracts; no assigned artifact/channel cell is inferred or omitted, and distribution does not substitute for the30-cell build evidence.
