Infrastructure: scripts/release_gate.sh

Purpose

scripts/release_gate.sh blocks releases that do not meet repository, branch, version, and documentation requirements.

It ensures:

  • develop has been merged into main.
  • Required Git refs are available and valid.
  • The requested version has not already been published.
  • The version in README.md matches the workspace version metadata.

A failure exits with status 1 and writes a release-gate: FAIL - ... message to stderr.

Key Targets/Stages

  1. Input validation
    Requires a release version from positional argument 3 or RELEASE_VERSION.

  2. Repository synchronization
    Fetches origin, prunes stale remote refs, fetches tags, and explicitly fetches the develop branch.

  3. Ref verification
    Confirms the configured main and develop refs resolve locally.

  4. Merge readiness
    Uses git merge-base --is-ancestor to verify that every commit on develop is included in main.

  5. Publication check
    Calls scripts/release_artifacts.py check-version-unpublished to ensure the requested version is not already published according to the artifact manifest.

  6. Documentation version check
    Calls scripts/release_artifacts.py verify-readme-version to validate that README.md is aligned with Cargo.toml.

Configuration

Invocation format:

scripts/release_gate.sh [main-ref] [develop-ref] [version] [manifest]

Defaults:

Input Default
main-ref origin/main
develop-ref origin/develop
version $RELEASE_VERSION
manifest release/publish-artifacts.toml

Example:

RELEASE_VERSION=1.2.3 scripts/release_gate.sh

Or with explicit values:

scripts/release_gate.sh origin/main origin/develop 1.2.3 release/publish-artifacts.toml

Operational Notes

  • Run this in a Git checkout with an origin remote and credentials sufficient to fetch branches and tags.
  • The script runs with set -euo pipefail; unset variables, command failures, and failed pipelines stop execution.
  • CI systems using shallow or single-branch checkouts are supported because the script explicitly fetches the configured develop branch.
  • A failure stating that develop has commits not in main means the release branch is incomplete; merge develop into main before retrying.
  • The Python 3 runtime and scripts/release_artifacts.py must be available in the repository checkout.
  • The gate performs validation only; it does not create tags, publish artifacts, merge branches, or modify release files.
