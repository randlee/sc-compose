File: prototype/multipass/types.py

Overview

prototype.multipass.types is the central Application-layer type model for the multi-pass template pipeline, producing shared pass-header, parsed-template, and render-context values consumed by parsing, rendering, validation, discovery, and verification. Its high dependency-graph centrality reflects its role as the common contract between components that progress a template through stacked rendering passes.

PassHeader describes one YAML frontmatter pass, including its ordinal position, required variables, defaults, and arbitrary metadata. ParsedTemplate combines the remaining pass headers with the template body. RenderContext supplies variables for a specific rendering pass.

Public API

PassHeader

@dataclass
class PassHeader:
    pass_number: int = 1
    required_variables: list[str] = field(default_factory=list)
    defaults: dict[str, Any] = field(default_factory=dict)
    metadata: dict[str, Any] = field(default_factory=dict)

Represents the configuration parsed from one pass-specific YAML frontmatter header.

  • pass_number is one-based and defaults to 1.
  • required_variables identifies values expected for the pass.
  • defaults provides fallback variable values.
  • metadata holds additional pass-specific configuration.

brace_count

@property
def brace_count(self) -> int

Returns pass_number + 1, which selects progressively deeper variable delimiters for later passes:

  • Pass 1: {{ ... }}
  • Pass 2: {{{ ... }}}
  • Pass 3: {{{{ ... }}}}

ParsedTemplate

@dataclass
class ParsedTemplate:
    passes: list[PassHeader]
    body: str

Represents a template after stacked pass headers have been separated from its renderable body.

pass_count

@property
def pass_count(self) -> int

Returns the number of remaining render passes.

is_fully_rendered

@property
def is_fully_rendered(self) -> bool

Returns True when passes is empty, indicating the template is ready for deployment or final output handling.

RenderContext

@dataclass
class RenderContext:
    pass_number: int
    variables: dict[str, Any] = field(default_factory=dict)

Carries the active pass number and its variable values into a rendering operation.

Dependencies

The module depends only on Python standard-library facilities:

  • dataclasses.dataclass defines the three lightweight value objects.
  • dataclasses.field creates independent mutable defaults for lists and dictionaries.
  • typing.Any permits YAML-derived defaults, metadata, and rendering variables to hold heterogeneous values.

It introduces no parser, renderer, YAML, CLI, or filesystem dependency, keeping the shared model portable across the multipass Application-layer modules.

Key consumers include:

  • parser.py, which constructs PassHeader and ParsedTemplate.
  • renderer.py, which consumes and returns ParsedTemplate values as passes are rendered.
  • e2e_demo.py and test modules, which create RenderContext values.
  • discover.py, validate_passes.py, and verify.py, which use these types as pipeline contracts.

Usage Notes

Construct PassHeader values when parsing each YAML frontmatter block. Use brace_count to configure delimiters so a pass resolves only the placeholders intended for that stage.

header = PassHeader(
    pass_number=2,
    required_variables=["environment"],
    defaults={"region": "us-west-2"},
)

assert header.brace_count == 3

Keep the parsed body and outstanding headers together in ParsedTemplate. Rendering code can remove or replace completed passes, then use is_fully_rendered to determine whether processing is complete.

template = ParsedTemplate(passes=[header], body="service: {{{ name }}}")

if template.pass_count == 1:
    context = RenderContext(pass_number=2, variables={"name": "api"})

Because collection fields use default_factory, each instance receives its own mutable list or dictionary; callers may safely add required variables, defaults, metadata, or context variables without affecting other instances.
