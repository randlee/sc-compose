File: crates/sc-compose/src/main.rs

Overview

main.rs is the Application-layer CLI entry point and orchestrator: it parses command-line input, initializes observability, dispatches commands, emits human or JSON output, and terminates the process with the selected exit code. It is a high-activity, high-complexity hotspot, so changes here can affect every sc-compose command and its output contract.

The file owns the binary’s process-wide setup:

  • Registers MiMalloc as the global allocator.
  • Parses the CLI through cli::parse_cli.
  • Determines whether the selected command requests JSON output.
  • Builds a CliObserver around the configured logger.
  • Delegates command execution to commands::dispatch::run.
  • Converts initialization and command failures into the appropriate output format and exit code.
  • Explicitly shuts down the observer before calling std::process::exit.

It also provides shared output helpers used by command implementations for diagnostics and JSON envelopes.

Public API

Although this is a binary entry point rather than a public library module, it exposes crate-visible helpers to sibling command modules.

Symbol Visibility Purpose
main() private Executes the application lifecycle: parse, initialize logging, dispatch, shut down, and exit.
print_diagnostic_messages(diagnostics) pub(crate) Prints each diagnostic’s message as a separate line to standard output.
print_json(payload, diagnostics) pub(crate) Serializes a payload and diagnostics through json_output::envelope, pretty-prints it to standard output, and propagates serialization failures.
CommandError pub(crate) re-export Makes the shared command error type available through the crate root.

Execution flow

  1. parse_cli() creates the parsed CLI model.
  2. command_wants_json(&cli.command) chooses the error/output mode before logger setup.
  3. observability::build_logger(wants_json) creates logging configuration, which is wrapped in observer_impl::CliObserver.
  4. commands::dispatch::run(cli, &mut observer) executes the selected subcommand.
  5. On completion, observer.shutdown() runs before process termination.
  6. std::process::exit(code) returns the command’s final status to the shell.

Logger initialization failures exit immediately after reporting; command-dispatch failures are reported and converted to their embedded exit_code.

Dependencies

Internal modules

  • cli supplies CLI parsing and JSON-mode detection.
  • commands supplies command dispatch and the implementations that call the shared output helpers.
  • command_error defines CommandError, including diagnostics and exit codes.
  • observability builds logging configuration.
  • observer_impl adapts logging into the command observer.
  • json_output wraps successful JSON results and diagnostics in a consistent envelope.
  • exit_codes, path_utils, render_request, template_store, var_file, and reporting are compiled as application modules for command-layer use.
  • main_tests is compiled only during tests.

External crates

  • anyhow supplies the fallible return type for JSON serialization.
  • mimalloc supplies the binary-wide allocator.
  • sc_composer supplies Diagnostic values produced by the rendering library.
  • serde and serde_json serialize structured CLI output.

Callers and callees

main calls CLI parsing, JSON-mode detection, logger construction, command dispatch, error reporting, observer shutdown, and process exit. Command handlers such as compose, template, verify, workspace, and report-scaffold commands call print_json or print_diagnostic_messages to maintain consistent output behavior.

Usage Notes

  • Keep main focused on orchestration. Command-specific behavior belongs under commands; rendering behavior belongs in sc-composer.
  • Determine JSON mode before initializing observability so setup failures use the same format requested by the command.
  • print_json writes to standard output and pretty-prints the entire envelope. Commands should avoid writing additional non-JSON text to standard output when JSON mode is active.
  • print_diagnostic_messages prints only Diagnostic::message; it does not include structured metadata, severity, or source locations.
  • In JSON error mode, print_json_error emits an empty payload plus cloned diagnostics. The CommandError text is only printed if JSON serialization itself fails. Error constructors therefore need meaningful diagnostics when callers require useful machine-readable failures.
  • main explicitly invokes observer.shutdown() because std::process::exit does not run normal stack unwinding or local destructors. Any new lifecycle-managed resource should be closed before that call.
  • An observer-construction error exits before an observer exists, while dispatch errors still pass through shutdown. Preserve this distinction if restructuring initialization.
  • This file is a hotspot: changes to exit sequencing, standard-output behavior, JSON envelopes, logging setup, or error reporting should be validated across both normal CLI and JSON CLI integration tests.
