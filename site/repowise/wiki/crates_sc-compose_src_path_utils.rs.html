Overview

path_utils is an Application-layer edge connector that validates relative paths and serializes PathBuf values into forward-slash strings for cross-layer CLI, reporting, and JSON consumers. It centralizes path-boundary rules so command handlers, observers, and reporting modules share the same portable representation and reject unsafe or ambiguous relative paths.

The module re-exports sc_composer::to_forward_slash for internal crate consumers, while its serializers adapt paths for Serde field attributes. Its validation helpers distinguish a path that is already normalized from one that must be checked and reconstructed.

Public API

All APIs are pub(crate): available throughout sc-compose, but not part of its external crate API.

Symbol Purpose
to_forward_slash Re-exported conversion helper from sc-composer; produces a slash-separated string representation of a path.
serialize_path Serde serialize_with callback for a required PathBuf; emits a string with forward slashes.
serialize_opt_path Serde callback for Option<PathBuf>; emits a slash-separated string for Some, or a serializer null/none value for None.
serialize_paths Serde callback for a slice of paths; emits a sequence of forward-slash strings.
is_normalized_relative_path Returns whether a path is non-empty, non-absolute, and consists only of normal path components.
normalize_relative_path Validates and rebuilds a normalized relative path, returning Result<PathBuf, String>.

normalize_relative_path rejects:

  • Empty paths, including paths that normalize to no components.
  • Absolute paths.
  • . components.
  • .. components.
  • Root and platform-prefix components, including Windows drive/UNC-style prefixes.

A successful result contains only Component::Normal segments, preserving component values while removing no input syntax implicitly—the function rejects invalid syntax instead of silently rewriting it.

Dependencies

  • std::path::{Path, PathBuf} provides platform-aware parsing and component iteration.
  • sc_composer::to_forward_slash supplies the shared path-to-string conversion used by all serialization helpers.
  • serde::Serializer is consumed through generic bounds to integrate with Serde without defining custom serializer types.

The module is consumed broadly by main, command modules, observability/observer code, and reporting code. Notable call paths include:

  • reporting/catalog.rs uses is_normalized_relative_path when assessing catalog path values.
  • commands/template_init.rs calls normalize_relative_path while accepting template-init path input.
  • reporting/publish_manifest.rs calls normalize_relative_path before writing manifest path data.
  • Serde-driven report and CLI JSON output uses the three serialization callbacks to keep emitted paths portable.

Usage Notes

Use the serializers through Serde’s serialize_with attribute when an output schema requires / separators regardless of the host operating system:

#[derive(serde::Serialize)]
struct Report {
    #[serde(serialize_with = "crate::path_utils::serialize_path")]
    output_path: std::path::PathBuf,

    #[serde(serialize_with = "crate::path_utils::serialize_opt_path")]
    source_path: Option<std::path::PathBuf>,
}

For collections, apply serialize_paths to a Vec<PathBuf> or compatible slice-backed field. It serializes each element independently and preserves sequence ordering.

Validate user- or configuration-provided relative paths before combining them with a workspace or output root:

let relative = crate::path_utils::normalize_relative_path(user_value.as_ref())
    .map_err(anyhow::Error::msg)?;

let destination = workspace_root.join(relative);

This validation should occur before join. Relying on PathBuf::join alone would permit .. segments or absolute input to change the intended destination. The helper intentionally does not collapse . or resolve ..; it rejects them so callers can surface a clear, stable error and avoid filesystem-dependent canonicalization.

Use is_normalized_relative_path when a boolean predicate is sufficient, such as filtering or asserting an already-validated internal value. Use normalize_relative_path when error messages are needed or when callers should receive a reconstructed PathBuf.

Do not use these helpers for paths that are intentionally absolute, paths that must permit parent traversal, or filesystem resolution. They enforce a logical path contract, not existence, symlink safety, or canonical filesystem identity.
