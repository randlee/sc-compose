File: prototype/multipass/renderer.py

Overview

prototype/multipass/renderer.py is an Application-layer multi-pass rendering orchestrator that consumes parsed stacked templates and per-pass contexts to produce fully rendered text through native sc_compose bindings. It applies each header-defined delimiter depth in order, merges header defaults with caller variables, and protects later-pass placeholders from premature evaluation.

The module exposes single-pass and full-sequence rendering APIs. It also includes private helpers for shielding higher-brace expressions and reconstructing header-prefixed template text.

Public API

render_pass(parsed, ctx) -> tuple[str, ParsedTemplate]

Renders the first remaining template pass and consumes its corresponding header.

  • Requires at least one remaining pass.
  • Verifies that ctx.pass_number matches the first header’s declared pass number.
  • Creates sc_compose.Renderer with delimiters based on the header’s brace_count.
  • Merges header.defaults and ctx.variables, with context variables taking precedence.
  • Returns the rendered body and a ParsedTemplate containing the unconsumed headers.

Raises ValueError when no passes remain or when the context and header pass numbers differ.

render_all(parsed, contexts) -> str

Renders every pass in order and returns the final text.

  • Requires exactly one RenderContext per parsed header.
  • Validates pass ordering before each render.
  • Delegates each iteration to render_pass.
  • Is called by the end-to-end demo and integration/full-render tests.

Raises ValueError if the number of contexts differs from the number of headers or if pass ordering is inconsistent.

Dependencies

  • sc_compose.Renderer provides the native rendering engine and supports per-pass custom variable delimiters through with_delimiters.
  • ParsedTemplate supplies the ordered pass headers and template body.
  • RenderContext supplies a pass number and its rendering variables.
  • yaml is imported locally by _reconstruct to serialize reconstructed header metadata.

render_pass calls _protect_higher_braces before native rendering. render_all sequences calls to render_pass.

Usage Notes

Passes are ordered outermost first. A pass with brace count 2 uses {{ ... }}, brace count 3 uses {{{ ... }}}, and so on; block delimiters remain {% ... %}.

Higher-brace expressions are wrapped in {% raw %} / {% endraw %} before the current pass renders. This prevents a lower-brace parser from treating part of a future-pass expression as its own variable syntax.

Provide contexts in the same order as parsed headers:

output = render_all(
    parsed_template,
    [
        RenderContext(pass_number=1, variables={"environment": "prod"}),
        RenderContext(pass_number=2, variables={"service": "api"}),
    ],
)

For callers that need to inspect intermediate output or retain unconsumed headers, use render_pass repeatedly instead of render_all.
