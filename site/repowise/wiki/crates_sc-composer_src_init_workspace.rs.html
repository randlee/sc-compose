File: crates/sc-composer/src/init_workspace.rs

Overview

init_workspace is an Application-layer workspace bootstrap orchestrator that creates and configures composed-output support while producing an InitResult containing discovered templates and validation diagnostics.

It canonicalizes the supplied repository root, determines whether .prompts/ and the .prompts/ .gitignore entry are missing, and scans the workspace for Jinja templates (*.j2). In normal mode it creates the directory and appends the ignore rule as needed; in dry-run mode it performs no filesystem writes but still scans and validates templates.

Each discovered template is converted into a file-mode ComposeRequest rooted at the canonical workspace, then passed to crate::validate. Validation warnings are accumulated as recommendations. Validation failures do not abort initialization: they set validation_passed to false and are converted into error-severity diagnostics.

Template discovery recursively traverses the workspace while skipping the root .git and target directories. This prevents version-control metadata and build output from being treated as input templates.

Public API

init_workspace

pub fn init_workspace(
    root: impl AsRef<Path>,
    dry_run: bool,
) -> Result<InitResult, ComposeError>

Bootstraps a workspace and validates all discovered .j2 templates.

Behavior:

  1. Canonicalizes root; invalid or inaccessible roots return ErrConfigParse.
  2. Scans recursively for case-insensitive .j2 extensions.
  3. Reads .gitignore, treating a missing file as empty.
  4. Determines whether .prompts/ must be created and whether .prompts/ must be added to .gitignore.
  5. In normal mode:
  6. creates .prompts/ when absent;
  7. appends .prompts/ to .gitignore when absent;
  8. rejects an already initialized workspace with ErrConfigReadonly.
  9. Validates every discovered template and returns aggregate results.

InitResult reports:

  • prompts_dir: canonical path to the workspace’s .prompts directory.
  • gitignore_updated: whether .prompts/ was absent before the operation.
  • scanned_templates: absolute template paths discovered during traversal.
  • recommendations: validation warnings and converted validation errors.
  • validation_passed: true only when every template validates successfully.

A dry run can return a successful result even when initialization would require writes, because it intentionally inspects planned work without changing the workspace.

read_optional_text_file

pub fn read_optional_text_file(path: &Path) -> Result<String, ComposeError>

Reads a UTF-8 text file, returning an empty string when the file does not exist. Other read failures, including attempting to read a directory as text, return ErrConfigRead.

This helper supports .gitignore handling without requiring callers to special-case a new workspace.

Dependencies

  • std::fs provides canonicalization, directory traversal, directory creation, file reading, and .gitignore writes.
  • std::path::{Path, PathBuf} represents workspace roots and discovered template paths.
  • std::collections::BTreeMap supplies empty variable maps for validation requests.
  • ComposeRequest, ComposeMode, ComposePolicy, and ConfiningRoot construct confined file-mode validation requests.
  • crate::validate validates each discovered template.
  • ComposeError, ConfigError, Diagnostic, and DiagnosticCode provide structured errors and validation reporting.
  • InitResult is the operation’s aggregate output type.

lib.rs exposes this module’s public helpers to library consumers. CLI integration tests invoke the exported behavior through the sc-compose command surface.

Usage Notes

A normal initialization flow:

use sc_composer::init_workspace;

let result = init_workspace("/path/to/repository", false)?;

println!("Prompts directory: {}", result.prompts_dir.display());
println!("Templates scanned: {}", result.scanned_templates.len());

if !result.validation_passed {
    for diagnostic in &result.recommendations {
        eprintln!("{diagnostic}");
    }
}

A safe inspection flow should use dry-run first:

let preview = init_workspace("/path/to/repository", true)?;

// No `.prompts/` directory or `.gitignore` modification is made.
for template in &preview.scanned_templates {
    println!("Would validate: {}", template.display());
}

Important behavior and pitfalls:

  • The root must already exist and be canonicalizable; relative roots are accepted but resolved to canonical paths.
  • A normal run against a workspace that already has both .prompts/ and the .prompts/ ignore rule fails intentionally with ErrConfigReadonly. Use dry_run: true to inspect such a workspace.
  • The .gitignore check compares trimmed lines exactly to .prompts/; alternate entries such as /.prompts/ are not considered equivalent and will result in another appended rule.
  • If .gitignore lacks a final newline, initialization inserts one before appending .prompts/.
  • Missing .gitignore is normal; unreadable existing .gitignore files are reported rather than silently ignored.
  • Template validation is best-effort across the whole scan: invalid templates become diagnostics instead of preventing the result from describing other templates.
  • Discovered template paths are absolute because scanning begins from the canonical root. The validation request converts each path back to a root-relative path when possible.
  • The scanner skips only root-level .git and target paths. Other directories are recursively traversed, so large workspaces may incur substantial traversal cost.
  • Extension matching is case-insensitive, so both example.j2 and example.J2 are included.
