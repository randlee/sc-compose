Overview

This repository has 281 files and 46,691 lines of code across 10 surveyed top-level directories. Its tree spans CLI and library code, Python bindings, documentation, reporting assets, automation, and prototypes; new contributors should start in crates/, then use docs/ for project guidance.

Top-level directories

docs/

This is the mostly-Markdown documentation area, including architecture, testing, team-process, sprint, and traceability material. Start with docs/index.md, then consult docs/traceability-matrix.md or docs/team-protocol.md for project context and collaboration rules.

.claude/

This directory contains agent-oriented Markdown skills, guidance, and assets. Begin with .claude/skills/team-lead/SKILL.md or .claude/skills/todo-triage/SKILL.md when looking for established agent workflows.

crates/

This is the Rust implementation area, covering the CLI and composition library. Start with crates/sc-compose/src/main.rs for the CLI, crates/sc-composer/src/lib.rs for the library surface, and crates/sc-compose/src/reporting/index.rs for reporting entry points.

prototype/

This contains Python prototype code under prototype/multipass. Read prototype/multipass/types.py first, then follow into discover.py, renderer.py, parser.py, and verify.py.

bindings/

This directory contains the Python binding implementation, with Rust source and Python package files. Start at bindings/python/src/lib.rs, then inspect bindings/python/python/sc_compose/__init__.py and bindings/python/src/convert.rs.

reports/

This holds report specifications, input material, and generated summary variables, primarily in TOML and JSON. Start with a relevant specification such as reports/specs/state-diagrams/retry-loop.toml, then inspect the summaries in reports/vars/.

(root)/

The repository root contains the primary project metadata and top-level guidance. Read README.md and Cargo.toml first; rust-toolchain.toml and RELEASING.md cover toolchain and release context.

.github/

This is CI, release, Pages, and action configuration. Start with .github/workflows/ci.yml, then read .github/workflows/release.yml or .github/actions/setup-python-release-build/action.yml for release automation.

scripts/

This directory contains supporting release, CI, reporting, and ATM scripts. Start with scripts/release_gate.sh or scripts/release_artifacts.py; scripts/tests/test_release_artifacts.py covers release-artifact checks.

pm/

This contains concise project-management and architecture-role notes. Read pm/arch-ccomp.md or pm/arch-comp.md for the available architectural perspectives.

If you're looking for…

  • the Rust CLI entry point → crates/sc-compose/src/main.rs
  • the composition library’s public surface → crates/sc-composer/src/lib.rs
  • reporting runtime code → crates/sc-compose/src/reporting/index.rs
  • Python bindings → bindings/python/
  • project, testing, or team documentation → docs/
  • report specs and report-summary inputs → reports/
  • CI and release workflows → .github/ and scripts/
  • prototype multipass code → prototype/multipass/

What's not here

For most implementation work, do not begin in .claude/, .github/, or pm/: they provide agent guidance, workflow automation, and role notes rather than the primary Rust or binding code.
