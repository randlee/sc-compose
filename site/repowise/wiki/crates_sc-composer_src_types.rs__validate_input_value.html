Symbol: crates.sc-composer.src.types.validate_input_value

Purpose

validate_input_value checks that an [InputValue] can be represented in the supported render-context model before it is used for template rendering.

It delegates validation to an internal recursive validator beginning at the top-level array context. This permits top-level arrays of objects, while rejecting unsupported structures deeper in the value tree, including nested arrays and arrays of objects at non-top-level paths.

Signature

fn validate_input_value(value: &InputValue) -> Result<(), InvalidInputValueError>

Parameters

  • value: &InputValue
    The caller-provided input value to validate. The value is borrowed and is not modified.

The validation begins with ArrayContext::TopLevel, which is significant because top-level arrays of objects are accepted even though the same shape is invalid when nested inside another value.

Returns

Returns:

Result<(), InvalidInputValueError>
  • Ok(()) when value fits the supported render-context model.
  • Err(InvalidInputValueError) when value contains an unsupported array structure, such as:
  • nested arrays;
  • an array of objects below the top level.

Top-level arrays of objects remain valid.

Example Usage

use sc_composer::types::{validate_input_value, InputValue};

let input = InputValue::from_json(r#"
[
  { "name": "Ada", "role": "engineer" },
  { "name": "Lin", "role": "designer" }
]
"#)?;

validate_input_value(&input)?;

A nested array is rejected:

use sc_composer::types::{validate_input_value, InputValue};

let input = InputValue::from_json(r#"
{
  "groups": [
    ["alpha", "beta"]
  ]
}
"#)?;

assert!(validate_input_value(&input).is_err());
