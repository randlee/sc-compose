Infrastructure: scripts/ci/validate_publish_order.sh

Purpose

scripts/ci/validate_publish_order.sh validates the crate publication order declared in release/publish-artifacts.toml.

It protects release automation from ambiguous or incorrectly ordered publishing by ensuring every crate has a unique publish_order and that manifest entries are already listed in ascending order.

Key Targets/Stages

  • Shell strict mode: set -euo pipefail causes the script to fail on command errors, unset variables, and pipeline failures.
  • Manifest loading: Python reads and parses release/publish-artifacts.toml with the standard-library tomllib module.
  • Duplicate-order validation: Fails if two crate entries use the same publish_order.
  • Ordering validation: Fails if crate entries are not already arranged by ascending publish_order.
  • Success output: Prints publish order validation passed when all checks succeed.

Configuration

The script has no command-line arguments or environment-variable configuration.

It expects to run from the repository root, where this path is available:

release/publish-artifacts.toml

The manifest must provide a crates collection whose entries include numeric or otherwise sortable publish_order values:

[[crates]]
name = "example-crate"
publish_order = 1

Python 3.11 or newer is required because tomllib was added to the Python standard library in Python 3.11.

Operational Notes

Run the validation from the repository root:

scripts/ci/validate_publish_order.sh

A non-zero exit indicates one of these release-manifest issues:

  • duplicate publish_order values detected — two or more crates share a publication position.
  • publish_order values must already be sorted in the manifest — crate entries are not listed in ascending publication order.

The check validates metadata only; it does not build, package, or publish crates. Use it in CI before release or publishing stages so dependency-aware publication order remains explicit and reviewable.
