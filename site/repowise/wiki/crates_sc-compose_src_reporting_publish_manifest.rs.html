File: crates/sc-compose/src/reporting/publish_manifest.rs

Overview

publish_manifest.rs is the Application-layer edge connector that builds and writes reports/latest/publish-manifest.json, translating the report index and archive layout into a publish-ready JSON manifest consumed by the reports publish command.

The module is part of the reporting subsystem’s public application-facing surface: commands/reports/publish.rs calls write_publish_manifest, while this file coordinates report-index validation, artifact-path normalization, archive discovery, JSON serialization, and filesystem output.

The generated manifest contains:

  • A UTC RFC 3339 generated_at timestamp.
  • One entry per publishable report.
  • Each report’s ID, kind, latest entrypoint, optional archived copy, and artifacts.
  • A destination path (publish_to) for every source artifact under reports/<report_id>/.

Required reports with missing evidence stop manifest generation. Optional reports with missing evidence are omitted entirely, so downstream publishing does not receive partial or invalid report entries.

    pub(crate) path: PathBuf,

}

Represents one report file to publish.

  • role is "entrypoint", "metadata", or "artifact".
  • path is the artifact’s repository-relative source path.
  • publish_to is its intended published destination, rooted at reports/<report_id>/.

Both paths use the project path serializer to produce stable JSON path representations.

PublishManifestError

Errors are categorized by operation and preserve contextual paths:

  • Index — report-index construction or required-evidence validation failed.
  • TimeFormat — RFC 3339 timestamp formatting failed.
  • InvalidArtifactPath — an artifact is outside its report’s latest-output root or normalizes unsafely.
  • ReadArchiveRoot — archive directory enumeration failed.
  • CreateDir — the manifest’s parent directory could not be created.
  • Serialize — JSON serialization failed.
  • Write — writing the manifest file failed.

The Display implementation includes relevant report IDs and paths, making command-level diagnostics actionable.

write_publish_manifest

pub(crate) fn write_publish_manifest(
    root: &Path,
) -> Result<PublishManifestResult, PublishManifestError>

Builds the report index beneath root, derives publish destinations, finds each report’s latest archive location, writes pretty JSON to PUBLISH_MANIFEST_RELATIVE_PATH, and returns the generated manifest.

Its caller is run_reports_publish_manifest in commands/reports/publish.rs.

time::OffsetDateTime / Rfc3339 Produces the generation timestamp.
std::fs Creates the output directory, writes the manifest, and inspects archive directories.

The module intentionally derives publish destinations from the latest report tree rather than accepting arbitrary destinations. For an artifact under:

reports/latest/<report_id>/subdir/file.json

it emits:

reports/<report_id>/subdir/file.json

This preserves artifact-relative structure while separating publish output from mutable reports/latest content.

Usage Notes

A typical caller supplies the repository root:

let result = write_publish_manifest(repo_root)?;
println!(
    "Wrote {} for {} reports",
    result.manifest_path.display(),
    result.report_count
);

The resulting JSON conceptually looks like:

{
  "generated_at": "2026-07-23T12:34:56Z",
  "reports": [
    {
      "report_id": "sc-lint",
      "kind": "lint",
      "entrypoint": "reports/latest/sc-lint/report.json",
      "archive_root": "reports/archive/2026-07-15T09-00-00Z/sc-lint",
      "files": [
        {
          "role": "entrypoint",
          "path": "reports/latest/sc-lint/report.json",
          "publish_to": "reports/sc-lint/report.json"
        }
      ]
    }
  ]
}

Generation proceeds in these stages:

  1. Build the report index from root.
  2. Reject a required report if its index entry lists missing evidence.
  3. Skip optional reports that have missing evidence.
  4. Verify each artifact lies beneath reports/latest/<report_id>.
  5. Normalize the remaining relative path before joining it to reports/<report_id>.
  6. Classify the artifact as the report entrypoint, metadata file, or a generic artifact.
  7. Locate the report’s newest matching archive directory, if any.
  8. Serialize and write the complete manifest.

Path validation is important. strip_prefix prevents an indexed artifact from being mapped into a publish destination when it does not belong to that report’s latest-output tree. normalize_relative_path then provides a second guard against unsafe or malformed relative paths before they are joined to the publish root.

Archive discovery does not require an archive for every report. If reports/archive is absent, the report is still included with archive_root: null. If archives exist, only directories that contain the requested report ID qualify; the implementation returns the lexically latest qualifying archive name. This assumes archive directory names sort chronologically, as demonstrated by timestamp-shaped directory names.

The module writes pretty-printed JSON and creates the manifest’s parent directory if necessary. Callers should treat successful return as confirmation that the file was written; the returned manifest is primarily useful for command output, tests, or additional in-process processing.
