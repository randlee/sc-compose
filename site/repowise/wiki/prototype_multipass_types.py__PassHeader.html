Symbol: prototype.multipass.types.PassHeader

Purpose

PassHeader represents the YAML frontmatter configuration for one rendering pass in the multipass prototype. It stores the pass number, variables required by that pass, default values, and arbitrary metadata.

Its brace_count property derives the number of braces used to delimit variables for the pass. This lets later passes use additional braces to avoid prematurely resolving placeholders intended for future passes.

    @property
    def brace_count(self) -> int:
        ...

Parameters

  • pass_number: int = 1
    The one-based render-pass number associated with this header. It also determines brace_count.

  • required_variables: list[str]
    Names of variables that must be available when this pass runs. Defaults to an empty list.

  • defaults: dict[str, Any]
    Default values for variables used by the pass. Defaults to an empty dictionary.

  • metadata: dict[str, Any]
    Additional pass-specific YAML frontmatter data that does not fit the standard fields. Defaults to an empty dictionary.

Returns

Constructing PassHeader returns a dataclass instance describing one render pass.

brace_count returns an int equal to pass_number + 1:

  • Pass 1 returns 2, corresponding to {{ variable }}.
  • Pass 2 returns 3, corresponding to {{{ variable }}}.
  • Pass 3 returns 4, corresponding to {{{{ variable }}}}.

Example Usage

from prototype.multipass.types import PassHeader

first_pass = PassHeader(
    pass_number=1,
    required_variables=["project_name"],
    defaults={"project_name": "sc-compose"},
    metadata={"description": "Initial template render"},
)

assert first_pass.brace_count == 2

second_pass = PassHeader(
    pass_number=2,
    required_variables=["generated_value"],
)

assert second_pass.brace_count == 3

The first pass uses ordinary Jinja-style delimiters such as {{ project_name }}. A second pass can preserve a variable for later evaluation with three braces, such as {{{ generated_value }}}.
