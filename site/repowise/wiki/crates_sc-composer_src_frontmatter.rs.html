Overview

frontmatter.rs is the Application-layer parser and normalizer for template YAML headers, producing ParsedTemplate values containing ordered Frontmatter passes, normalized configuration, diagnostics, and the delimiter-free template body. It is a high-activity, high-complexity hotspot: changes here affect parsing, validation, composition, CLI custom-delimiter rendering, and compatibility behavior.

The module recognizes one or more leading YAML frontmatter blocks delimited by --- and terminated by either --- or .... It deliberately parses only the contiguous header stack at the beginning of the document; later delimiter-looking lines remain part of the body.

Normalization converts deserialized YAML into domain types:

  • Required variable names become validated VariableName values and must be unique.
  • Default values become validated InputValue values.
  • Metadata remains YAML-backed MetadataValue.
  • Missing collection fields become explicit empty collections.
  • Omitted or zero pass numbers become default_pass_number().
  • Conflicting defaults and input_defaults sections produce a warning while allowing input_defaults to override duplicate keys.

Malformed YAML, an unclosed opening delimiter, invalid variable names or values, duplicate required variables, and duplicate explicitly declared pass numbers all fail closed with ComposeError values enriched with configuration recovery hints.

Public API

Frontmatter

A normalized, typed representation of one YAML frontmatter header.

  • Frontmatter::empty() -> Frontmatter
    Creates an empty header using the configured default pass number and empty collections.

  • pass_number(&self) -> u8
    Returns the effective pass number. pass: 0 and an omitted pass both normalize to the default pass number.

  • required_variables(&self) -> &[VariableName]
    Returns required variables in declaration order.

  • defaults(&self) -> &BTreeMap<VariableName, InputValue>
    Returns normalized default input values. The BTreeMap gives callers deterministic key ordering.

  • metadata(&self) -> &BTreeMap<String, MetadataValue>
    Returns descriptive metadata without treating it as input defaults.

  • diagnostics(&self) -> &[Diagnostic]
    Returns non-fatal normalization warnings, currently including conflicting default-section usage.

has_explicit_pass_number is crate-private. It distinguishes an explicitly declared pass from an effective default pass, allowing duplicate explicit passes to be rejected without rejecting several omitted/defaulted passes.

ParsedTemplate

The parsed document boundary shared by rendering and validation.

  • ParsedTemplate::from_parts(passes, body) -> ParsedTemplate
    Crate-private constructor for already-normalized, internally trusted parts. Used by composition flows.

  • ParsedTemplate::from_parts_validated(passes, body) -> Result<ParsedTemplate, ComposeError>
    Public constructor for normalized parts that re-validates duplicate explicit pass numbers. This is appropriate when callers rebuild or transform parsed passes outside the direct parser path.

  • frontmatter(&self) -> Option<&Frontmatter>
    Returns the outermost header, preserving the legacy single-header access pattern.

  • passes(&self) -> &[Frontmatter]
    Returns all leading headers in outer-to-inner order.

  • body(&self) -> &str
    Returns the remaining document content after the complete leading header stack.

parse_template_document

pub fn parse_template_document(input: &str) -> Result<ParsedTemplate, ComposeError>

Parses a template document into normalized passes and body text.

Typical outcomes:

Input shape Result
No leading delimiter No passes; entire input is the body
One leading YAML block One normalized pass; remaining input is the body
Consecutive leading YAML blocks Multiple ordered passes; remaining input is the body
--- inside body after a parsed header Preserved verbatim in the body
Opening --- without a closing delimiter Configuration parse error
Invalid YAML or unsupported input value Configuration/validation error

Dependencies

The module depends on:

  • serde::Deserialize and serde_yaml to deserialize the internal RawFrontmatter transport structure.
  • std::collections::BTreeMap and BTreeSet for deterministic mappings and duplicate detection.
  • crate::types for domain validation and conversion:
  • VariableName validates input-variable identifiers.
  • InputValue is produced by input_value_from_yaml.
  • MetadataValue preserves metadata values.
  • default_pass_number supplies the canonical effective pass.
  • crate::diagnostics for warning collection when compatible configuration forms conflict.
  • crate::error for ComposeError, typed configuration/validation failures, diagnostic codes, and recovery hints.

Its primary downstream consumers are:

  • composer.rs, which constructs parsed templates during composition and renders ParsedTemplate::body().
  • validation.rs, which examines parsed frontmatter and pass numbers when collecting validation state.
  • frontmatter_init.rs and include.rs, which consume normalized frontmatter as part of template setup and inclusion behavior.
  • sc-compose command handling, whose custom-delimiter render path uses ParsedTemplate::from_parts_validated.
  • lib.rs, which re-exports the public parsing surface.

Usage Notes

Parse a document with no header:

let parsed = parse_template_document("Hello, {{ name }}!")?;

assert!(parsed.passes().is_empty());
assert_eq!(parsed.body(), "Hello, {{ name }}!");
assert!(parsed.frontmatter().is_none());

Parse a single frontmatter pass:

let parsed = parse_template_document(
    "---\npass: 2\nrequired_variables: [name]\ndefaults:\n  greeting: Hello\n---\n{{ greeting }}, {{ name }}!"
)?;

let header = parsed.frontmatter().expect("one frontmatter header");
assert_eq!(header.pass_number(), 2);
assert_eq!(header.required_variables().len(), 1);
assert_eq!(parsed.body(), "{{ greeting }}, {{ name }}!");

Parse stacked passes when a template requires multiple composition stages:

let parsed = parse_template_document(
    "---\npass: 1\ndefaults: { name: World }\n---\n---\npass: 2\nmetadata: { stage: final }\n...\nHello, {{ name }}!"
)?;

assert_eq!(parsed.passes().len(), 2);
assert_eq!(parsed.passes()[0].pass_number(), 1);
assert_eq!(parsed.passes()[1].pass_number(), 2);

Be careful when reconstructing a ParsedTemplate. from_parts assumes the caller has already upheld invariants; use from_parts_validated across public or externally assembled boundaries so duplicate explicit pass numbers cannot bypass parser validation.

Delimiter recognition is intentionally strict:

  • The first header must begin exactly at byte zero.
  • Opening delimiters must be ---\n, ---\r\n, or exactly --- at end of input.
  • Closing delimiters must occupy a line by themselves after trimming line endings.
  • Only consecutive leading blocks are consumed. A later --- is template body content, not a new header.

Defaults deserve particular attention. Both defaults and input_defaults are accepted, then merged into one map. If both are present, input_defaults overwrites overlapping keys and emits a warning accessible through Frontmatter::diagnostics(). Consumers should preserve and surface those diagnostics instead of silently discarding compatibility warnings.
