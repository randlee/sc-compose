Overview

convert.rs is the Application-layer edge connector that translates Python binding inputs into validated sc_composer domain values and converts JSON-compatible results back into Python objects. It forms the shared conversion boundary for the Python API: request, policy, result, function, and module bindings consume its crate-private helpers to normalize Python values before entering the pure composer library.

The module accepts both Python wrapper classes (PyProfileName, PyConfiningRoot, PyNamedTemplateAsset, PyPassConfig, and PyVariableName) and selected native Python representations such as strings, dictionaries, iterables, tuples, and os.PathLike objects. It preserves domain invariants by delegating name, root, runtime, and input validation to sc_composer and translating failures into binding-specific configuration or validation exceptions.

It also implements a recursive JSON bridge. Python None, booleans, finite numbers, strings, dictionaries with string keys, and iterables are converted to serde_json::Value; JSON values are reconstructed as Python None, scalars, lists, and dictionaries. This allows Python callers to supply nested contexts without exposing Rust serialization details.

Public API

All functions are pub(crate), so they are internal to the Python bindings crate rather than Python-callable exports themselves. Their consumers construct Python-facing objects and invoke composition operations.

Function Produces Behavior
extract_supporting_templates Vec<NamedTemplateAsset> Converts an optional iterable of PyNamedTemplateAsset instances. Missing input becomes an empty vector.
extract_profile_name ProfileName Accepts a PyProfileName wrapper or a string, validating string values through ProfileName::new.
extract_runtime_kind Option<RuntimeKind> Delegates optional runtime parsing to parse_runtime_kind.
extract_allowed_roots Vec<ConfiningRoot> Accepts wrapped roots or Python path-like values, normalizing the latter through os.fspath before domain validation.
extract_string_map BTreeMap<String, InputValue> Converts a required Python dictionary with string keys into validated compose input values.
extract_var_map BTreeMap<VariableName, InputValue> Converts an optional dictionary into validated variable names and validated JSON-compatible values.
extract_variable_names Vec<VariableName> Converts an optional iterable of PyVariableName wrappers or strings into validated variable names.
extract_metadata_map BTreeMap<String, MetadataValue> Converts optional metadata dictionaries through JSON and deserializes values into MetadataValue.
extract_pass_configs Vec<PassConfig> Requires each iterable entry to be a PyPassConfig instance.
extract_pass_contexts Vec<(u8, BTreeMap<VariableName, InputValue>)> Requires each entry to be a two-item (pass_number, variables) tuple and validates its variable map.
extract_json_context InputValue Converts and validates one arbitrary JSON-compatible Python value.
coerce_path_like String Invokes Python’s os.fspath protocol to obtain a path string.
json_to_py Py<PyAny> Recursively converts serde_json::Value into Python scalars, lists, and dictionaries.
py_to_json_value serde_json::Value Recursively converts supported Python values into JSON, rejecting unsupported types, non-string object keys, and non-finite floats.

Validation and error behavior

  • Missing optional collections consistently become empty collections; a supplied value must still satisfy the expected Python shape.
  • Dictionary-oriented helpers use BTreeMap, providing deterministic key ordering in the Rust representation.
  • extract_string_map, extract_var_map, and extract_json_context call sc_composer::validate_input_value, so Python contexts obey the same input restrictions as other composer front ends.
  • Invalid variable names are rejected at the binding boundary with ScValidationError rather than being allowed into later rendering stages.
  • Metadata deserialization failures are configuration errors (ERR_CONFIG_PARSE), while malformed Python container shapes and unsupported values are validation errors.
  • py_to_json_value checks booleans before integers, preventing Python bool values from being represented as numeric JSON values.
  • Python iterables that are not dictionaries are treated as JSON arrays. This includes tuples and other iterable objects; callers should avoid passing strings where an array is intended, because Python strings are extracted as scalars first.

Conversion examples

from pathlib import Path

# Policy/root conversion accepts native path-like values.
allowed_roots = [Path("templates"), "/srv/shared-templates"]

# Variable maps require string keys that satisfy VariableName validation.
variables = {
    "environment": "production",
    "feature_flags": {"audit": True},
    "replicas": 3,
}

# Per-pass contexts must be exactly (u8 pass number, variables mapping).
contexts = [
    (1, {"region": "us-west"}),
    (2, {"region": "eu-central"}),
]

The equivalent Rust-side processing is:

  1. The binding object passes Python arguments to an extractor.
  2. The extractor verifies the required container or wrapper type.
  3. Nested values are converted by py_to_json_value.
  4. Domain constructors and validate_input_value enforce composer rules.
  5. Any failure is surfaced as a Python binding error with a user-facing message and, where available, an error code.

Dependencies

  • pyo3 supplies Python, PyAny, PyDict, PyList, PyBool, wrapper extraction, iteration, and Python exception propagation.
  • sc_composer provides the domain types (ProfileName, VariableName, ConfiningRoot, RuntimeKind, InputValue, MetadataValue, and NamedTemplateAsset) and input validation.
  • crate::enums::parse_runtime_kind centralizes Python-facing runtime-kind parsing.
  • crate::errors::{config_error, validation_error} maps Rust/domain failures into the binding’s Python exception model.
  • crate::types supplies Python wrapper classes whose inner values are cloned into domain objects.
  • serde_json is the intermediate representation for recursive Python context and metadata conversion.
  • std::collections::BTreeMap stores maps in a deterministic order.

Key dependents include functions.rs, lib.rs, and Python binding types for policies, requests, and results. In particular, request construction uses the template, runtime, variable, pass, and context extractors, while policy construction uses profile and allowed-root extraction.

Usage Notes

  • Prefer the provided Python wrapper classes when an API exposes them; the extractors preserve their already-validated inner values.
  • Use strings for profile and variable names only when callers need convenience construction. Those strings are validated immediately and may raise configuration or validation errors.
  • Pass dictionaries—not mapping-like custom objects—to context, variables, and metadata parameters. The module explicitly requires PyDict.
  • JSON object keys must be strings. Nested dictionaries with integer, enum, or arbitrary object keys are rejected.
  • Only finite floating-point values are supported. Python float("nan"), positive infinity, and negative infinity cannot be represented in JSON and produce validation errors.
  • For roots, pathlib.Path is supported through os.fspath; this is preferable to manually converting paths to strings in Python code.
  • extract_pass_contexts requires a strict two-item tuple and a pass number representable as u8 (0 through 255).
  • json_to_py preserves the JSON data model, not Python-specific types: JSON arrays become lists and objects become dictionaries.
  • The unit tests cover recursive JSON round-tripping and invalid variable-name rejection. Changes to recursive conversion ordering or error mapping should retain both guarantees.
