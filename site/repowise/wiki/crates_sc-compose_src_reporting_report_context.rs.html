Overview

report_context.rs is an Application-layer adapter that converts a SourceEntry into serializable ReportTemplateContext and ReportPanel data consumed by report rendering templates.

It prepares a single-panel context with a report title, source body, optional copy and fragment metadata, and normalized path metadata. Panel IDs derive from normalized source paths so the same logical path produces a consistent identifier across separator styles.

Public API

  • ReportPanel — crate-private serializable template panel containing:
  • panel_id
  • title
  • body
  • copy_text
  • optional copy_json

  • optional fragment_href

  • ReportTemplateContext — crate-private serializable report context containing a title, panels, and optional metadata map.

  • context_from_source_entry(entry, report_title) — builds a one-panel template context. Uses report_title when supplied; otherwise derives the title from entry metadata or the source filename.

  • entry_title(entry) — resolves "title" metadata, falling back to the source file stem and finally "report-panel".

  • stable_path_key(path) — converts a path to forward slashes, then replaces every non-alphanumeric character with - for use as a stable panel ID.

Dependencies

  • reporting::source_entry::SourceEntry supplies source/output paths, metadata, sets, and rendered body content.
  • path_utils::to_forward_slash normalizes path separators before metadata or ID generation.
  • serde::Serialize makes context structures available to the template serialization pipeline.
  • serde_json::Value preserves structured metadata and serializes optional copy_json.
  • BTreeMap stores report metadata in deterministic key order.

render_many.rs calls context_from_source_entry while rendering entries, and templates.rs consumes the resulting context fields to construct render data.

Usage Notes

  • report_metadata always includes normalized source_path and output_path; it includes sets only when present on the source record.
  • copy_json serializes the entire metadata value under "copy_json"; serialization failure falls back to the JSON literal "null".
  • fragment_href prefers "fragment_href" metadata and falls back to "fragment".
  • The public surface is pub(crate), so these types and helpers are intended for internal reporting workflows rather than external crate consumers.
  • Tests verify that slash and backslash paths yield identical keys and that generated panel IDs remain stable.
