File: crates/sc-compose/src/reporting/source_entry.rs

Overview

source_entry.rs is the Application-layer source-entry loader and metadata parser that consumes report source files and produces normalized SourceEntry records, renderable bodies, and path-aware validation errors.

It provides the boundary between discovered input files and the reporting pipeline. render_many::discover_sources calls SourceEntry::load for each source, while downstream reporting code uses the resulting record, original source text, and parsed body to build report context and render output.

The module supports three input forms:

  • A .toml report specification, parsed by parse_report_spec and rendered to Mermaid text through render_mermaid.
  • A leading /* ... */ metadata block containing YAML.
  • Consecutive leading comment lines using #, //, --, or ;, also containing YAML.

When no recognized metadata form is present, the whole file remains the body and metadata is empty. This lets ordinary source files participate in reporting without requiring a front-matter convention.

Public API

SourceEntry

A crate-visible, immutable-style container for one discovered reporting source.

Field Purpose
record: SourceEntryRecord Serializable source/output paths plus normalized metadata and optional set membership.
raw_source: String Exact file contents as read from disk.
body: String Source content after metadata extraction, or generated Mermaid text for TOML report specs.

SourceEntry::load

pub(crate) fn load(
    absolute_source_path: &Path,
    source_path: &Path,
    output_path: PathBuf,
) -> Result<SourceEntry, SourceEntryError>

Reads absolute_source_path, parses its metadata/body, and associates the logical source_path and intended output_path with the result.

The two source-path parameters intentionally serve different roles:

  • absolute_source_path is used for filesystem I/O.
  • source_path is retained in records and errors, so diagnostics use the reporting-relative or user-facing path rather than a machine-specific absolute path.

SourceEntryRecord

A serializable description of a source entry:

pub(crate) struct SourceEntryRecord {
    pub(crate) source_path: PathBuf,
    pub(crate) output_path: PathBuf,
    pub(crate) metadata: BTreeMap<String, serde_json::Value>,
    pub(crate) sets: Option<Vec<String>>,
}

Both paths use crate::path_utils::serialize_path, ensuring path representation is handled consistently when records are serialized. Metadata is sorted by key through BTreeMap, which makes serialized/report-context ordering deterministic.

sets is extracted from metadata instead of being retained inside metadata; consumers can therefore use set membership directly without interpreting arbitrary JSON metadata.

SourceEntryError

Error type returned by loading and metadata processing.

  • Read { path, source } wraps filesystem read errors.
  • InvalidMetadata { path, message } reports malformed YAML, invalid metadata shapes, invalid TOML report specs, or Mermaid rendering failures.

Its Display implementation includes the logical source path, and it implements std::error::Error.

Metadata parsing behavior

parse_metadata is private but defines the module’s core precedence rules:

  1. If the file extension is exactly toml, try parsing it as a report spec.
  2. If a report spec is recognized, derive metadata and sets from the spec, then generate the body with render_mermaid.
  3. Otherwise, inspect for a leading block-comment metadata section.
  4. Otherwise, inspect consecutive leading line comments.
  5. Otherwise, return empty metadata and the original source as the body.

A TOML file that does not match a report-spec shape is not automatically rejected; parsing proceeds to the comment-based formats and finally falls back to raw content. A TOML file recognized as a report spec, however, fails loading if its metadata extraction or Mermaid rendering fails.

YAML metadata requirements

Parsed YAML must be a mapping with string keys.

  • All fields except sets are converted to serde_json::Value and added to metadata.
  • sets must be a YAML sequence containing only strings.
  • Empty metadata comments are valid and produce empty metadata.
  • A scalar, sequence, or non-string mapping key produces InvalidMetadata.

Example block metadata:

/*
title: Release report
owner: docs
sets:
  - weekly
  - internal
*/
# Report content starts here

Equivalent prefix-comment metadata:

# title: Release report
# owner: docs
# sets:
#   - weekly
#   - internal
# Report content starts here

For prefix comments, metadata ends at the first non-comment line. Comment-looking lines later in the body are preserved as body content.

The module is consumed by reporting::render_many, which discovers and loads sources, and by reporting::report_context and reporting::mod, which use normalized source-entry data during report assembly.

Usage Notes

A normal caller should construct entries through SourceEntry::load, rather than parsing content independently:

let entry = SourceEntry::load(
    &workspace_root.join("reports/system.md"),
    Path::new("reports/system.md"),
    PathBuf::from("generated/system.html"),
)?;

let title = entry.record.metadata.get("title");
let body = &entry.body;

For a TOML report specification, the loaded entry retains the original TOML in raw_source, but body contains Mermaid generated from the parsed spec:

let entry = SourceEntry::load(
    &workspace_root.join("reports/dependencies.toml"),
    Path::new("reports/dependencies.toml"),
    PathBuf::from("generated/dependencies.html"),
)?;

// Preserve original TOML for inspection or hashing.
assert!(!entry.raw_source.is_empty());

// Render the generated Mermaid representation.
render_report_body(&entry.body)?;

Be careful with the following edge cases:

  • Block metadata is recognized only when the first non-whitespace content begins with /*. Leading spaces, tabs, and blank lines are allowed.
  • The block parser removes only leading newlines after */; spaces after the closing delimiter remain in the body.
  • Prefix metadata accepts indented comment markers because each line is left-trimmed before prefix detection.
  • Prefix comment markers are limited to #, //, --, and ;; unsupported markers cause the file to fall back to raw-body behavior.
  • A blank line ends prefix metadata, even if subsequent lines are comments.
  • The sets key is reserved. It is not copied into record.metadata, and values such as sets: all or numeric list items are errors.
  • YAML keys must be strings. YAML allows other mapping-key types, but this module deliberately rejects them because metadata is represented as BTreeMap<String, Value>.
  • raw_source and body may differ substantially for TOML specs; downstream code should choose deliberately between original content and report-renderable content.
  • Errors expose source_path, not absolute_source_path, so callers should pass the logical path that users expect to see in diagnostics.
