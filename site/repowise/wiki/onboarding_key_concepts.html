Overview

This repository is a template-composition toolchain: the core concepts span typed frontmatter and multipass rendering, with diagnostics and verification around the resulting work. The code-facing model sits alongside detected repository clusters such as .atm, .mcp, agents, and assets/sc-rust.

Core concepts

ParsedTemplate

ParsedTemplate represents a template as stacked pass headers plus its body. It is the central multipass unit: the headers describe remaining work, while the body is the content being progressively rendered.

Where it lives: prototype/multipass/types.py

PassHeader

PassHeader is one YAML frontmatter header for a render pass. Its pass-oriented metadata determines how that layer of a ParsedTemplate is interpreted, including the delimiter-brace depth and the number of passes still to perform.

Where it lives: prototype/multipass/types.py

RenderContext

RenderContext holds the variables supplied to one render pass. It separates pass-specific inputs from the template structure, making each rendering step explicit.

Where it lives: prototype/multipass/types.py

frontmatter

frontmatter provides typed parsing and normalization for frontmatter. It is the structured boundary for metadata before that metadata participates in the rest of template processing.

Where it lives: crates/sc-composer/src/lib.rs

diagnostics

diagnostics provides structured diagnostics and the stable ERR_* code registry. It gives failures and validation outcomes a consistent, machine-recognizable form.

Where it lives: crates/sc-composer/src/lib.rs

verify

verify exposes drift-verification entrypoints. It is the checking surface for determining whether the composed result remains aligned with its expected state.

Where it lives: crates/sc-composer/src/lib.rs

How they connect

frontmatter establishes typed, normalized metadata, while ParsedTemplate models a template as a body with stacked PassHeader values. Each PassHeader describes one stage: its brace-count behavior distinguishes the variable delimiters for that pass, and its pass count records how much rendering remains. A RenderContext supplies the variables for each individual stage, allowing the template to advance pass by pass. When no pass remains, ParsedTemplate is fully rendered and ready for deployment. Around this flow, diagnostics gives structured error reporting, and verify provides the entrypoints for checking drift.
