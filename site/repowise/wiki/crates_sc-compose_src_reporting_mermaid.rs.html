Overview

The Application-layer Mermaid renderer dispatches ReportSpec values into Mermaid state-diagram or flowchart text and returns rendering validation errors when required structural data is absent.

render_mermaid selects the renderer from the ReportSpec variant. State-machine specs produce stateDiagram-v2 output with declared states, terminal-state edges, and annotated transitions. SQL-query specs produce flowchart TD output connecting the query to read/write tables and optional filter, ordering, transaction, and cardinality metadata.

Public API

  • pub(crate) fn render_mermaid(spec: &ReportSpec) -> Result<String, MermaidRenderError>
    Application-facing dispatcher for Mermaid rendering. It accepts either ReportSpec::StateMachine or ReportSpec::SqlQuery.

  • pub(crate) struct MermaidRenderError
    Renderer error type. Its Display implementation exposes the validation message, and it implements std::error::Error.

Internal helpers:

  • render_state_machine rejects specs with no states, renders labeled or unlabeled state declarations, and emits terminal and transition edges.
  • render_sql_query rejects specs with neither read nor written tables, then renders the query’s table relationships and optional metadata nodes.
  • sanitize_node_id converts all non-alphanumeric characters to _ for Mermaid node identifiers. It is not collision-safe: for example, build:ok and build/ok both become build_ok.

Dependencies

  • std::fmt supplies formatting support for MermaidRenderError.
  • crate::reporting::spec::{ReportSpec, StateMachineSpec, SqlQuerySpec} supplies the typed report specifications consumed by the renderer.
  • crates/sc-compose/src/reporting/mod.rs exposes this reporting component to the surrounding module.
  • Reporting flows such as spec rendering and source-entry metadata parsing call render_mermaid to obtain Mermaid output.

Usage Notes

Call render_mermaid after parsing and validating a report specification:

let mermaid = render_mermaid(&report_spec)?;

State-machine rendering requires at least one state. Transition labels concatenate available event, guard, actor, and effect fields.

SQL-query rendering requires at least one table in tables_read or tables_written. Read/write relationships use solid edges; filters, ordering, transactional assumptions, and cardinality use dotted edges.

Titles and metadata are interpolated directly into Mermaid labels. Callers should ensure supplied text is suitable for Mermaid syntax.
