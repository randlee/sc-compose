Overview

CommandError is the Application-layer error adapter and cross-layer edge connector that consumes command and sc_composer failures and produces CLI exit codes, structured diagnostics, recovery hints, and display-ready error messages. It gives command handlers, reporting modules, observability setup, and main.rs one consistent failure representation while preserving the underlying anyhow::Error.

compose translates each ComposeError variant into the CLI’s exit-code policy and extracts diagnostics and applicable recovery hints. Display prefixes messages with an optional diagnostic code and appends each recovery action on a separate recovery: line.

Public API

All items are pub(crate), so they are available throughout the sc-compose crate but are not part of its external library API.

  • CommandError
  • exit_code: i32 — process status to return.
  • diagnostic_code: Option<DiagnosticCode> — optional stable machine-readable error code.
  • diagnostics: Vec<Diagnostic> — structured diagnostics for JSON or other reporting.
  • recovery_hints: Vec<RecoveryHint> — actionable remediation guidance.

  • error: anyhow::Error — underlying human-readable failure.

  • CommandError::usage(error) creates an unstructured usage failure with USAGE_FAIL.

  • CommandError::usage_with_code(error, diagnostic_code) creates a usage failure with one error diagnostic.

  • CommandError::usage_with_code_and_hints(error, diagnostic_code, recovery_hints) adds caller-provided remediation guidance to a coded usage failure.

  • CommandError::compose(error) adapts a ComposeError:

  • validation, render, and include errors use VALIDATION_OR_RENDER_FAIL;
  • resolve and configuration errors use USAGE_FAIL;
  • validation and configuration errors retain their recovery hints;

  • include errors retain their include chain in the emitted diagnostic.

  • CommandError::render_write(error) creates an ErrRenderWrite failure.

  • CommandError::stdin_double_read() reports ErrRenderStdinDoubleRead when both guidance and prompt attempt to consume standard input.

CommandError implements std::error::Error and Display. A coded error renders as <diagnostic-code>: <error>; recovery hints render as recovery: <action>.

Dependencies

  • anyhow supplies the erased Error type and converts ComposeError into the stored underlying error.
  • sc_composer supplies the domain error and diagnostic model: ComposeError, Diagnostic, DiagnosticCode, DiagnosticSeverity, RecoveryHint, and RecoveryHintKind.
  • crate::exit_codes supplies the CLI-specific process-status constants.
  • std::fmt supports the CLI-facing Display implementation.

This module is consumed by main.rs for text and JSON error reporting, command dispatch and command implementations for failure construction, and reporting, rendering, variable-file, and observability paths that need to normalize failures.

Usage Notes

Command code should construct the most specific variant available:

  • Use compose for failures received from sc_composer, so diagnostics, include chains, exit codes, and supported recovery hints are preserved.
  • Use usage_with_code_and_hints for CLI argument or configuration mistakes where the caller knows the diagnostic code and corrective action.
  • Use render_write for output-write failures and stdin_double_read for the explicit competing-stdin condition.
  • Consumers that need machine-readable output should use diagnostics; terminal-oriented reporting can display the error directly and use recovery_hints as needed.
  • Avoid wrapping a ComposeError with plain usage, because that discards its structured diagnostics and recovery metadata.
