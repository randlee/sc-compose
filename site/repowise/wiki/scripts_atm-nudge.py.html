File: scripts/atm-nudge.py

Overview

atm-nudge.py is the Docs & Tooling layer entry-point dispatcher for ATM post-send delivery, resolving an agent’s authoritative tmux pane and producing tmux keystrokes, structured diagnostics, and hook results.

It is invoked as a standalone script rather than imported by application code. In normal mode, it discovers the repository-local .atm.toml, identifies the requested recipient by name and ATM team, builds an ATM instruction payload, and sends it to the resolved tmux pane. In override mode, --pane bypasses lookup and delivers directly to the supplied pane ID.

This is a hotspot file with high change frequency and complexity. Changes can affect message delivery, recovery guidance, and the relationship between committed pane configuration and Claude’s local team configuration; test both successful and failure paths carefully.

The central delivery policy is deliberate:

  • .atm.toml is the authoritative, repository-scoped pane mapping.
  • ~/.claude/teams/<team>/config.json is advisory only.
  • A valid .atm.toml mapping still delivers even when config.json is missing, invalid, or stale.
  • A mismatch produces a warning with remediation instructions rather than blocking delivery.

Resolution starts from CLAUDE_PROJECT_DIR, then PWD, then os.getcwd(), walking upward from each candidate directory until it finds .atm.toml. Team selection prioritizes ATM_POST_SEND.team, then .atm.toml defaults, then ATM_TEAM, and finally sc-compose.

Public API

Although this is primarily a CLI script, its functions form clear internal extension points.

Symbol Role
PaneLookup Named tuple carrying pane_id, error code/message, and optional source path.
candidate_start_dirs() Collects unique, resolvable directories used to begin .atm.toml discovery.
find_atm_toml(start_dir) Walks from a directory to the filesystem root looking for .atm.toml.
discover_atm_toml() Tries each candidate start directory and returns the first .atm.toml found.
read_post_send_payload() Parses ATM_POST_SEND JSON safely; malformed or non-object values become {}.
resolve_team() Resolves the effective team from post-send payload, TOML defaults, environment, or fallback.
read_pane_from_toml(recipient, team) Reads the authoritative pane mapping and returns a structured lookup result.
read_pane_from_config(recipient, team) Reads advisory Claude config.json pane information.
nudge_pane(pane_id, recipient, message) Validates inputs, sends literal text through tmux, presses Enter, and logs delivery.
build_message(team, payload) Produces default ATM XML-like instructions, including special acknowledgement behavior.
build_nudge_command(pane, recipient, message) Builds a shell-safe manual recovery command using shlex.join.
build_error_payload(...) Produces detailed JSON diagnostics when authoritative lookup prevents delivery.
build_warning_payload(...) Produces JSON remediation guidance after delivery succeeds but advisory config is inconsistent.
emit_json_stderr(data) Prints pretty JSON diagnostics to stderr.
emit_hook_result(level, message, fields) Emits compact JSON hook output to stdout.
main(argv) Parses arguments, coordinates resolution and delivery, and returns a process status.

CLI contract

atm-nudge.py [--pane <id>] <recipient> [<message>]
  • <recipient> is required.
  • <message> is optional; when absent, the script generates an ATM action message.
  • --pane <id> directly targets a tmux pane and skips .atm.toml and config.json lookup.
  • Exit status 0 means delivery succeeded, including delivery with an advisory warning.
  • Exit status 1 means arguments were invalid or authoritative pane resolution failed.

Resolution behavior

read_pane_from_toml() searches [[rmux.windows.panes]] entries:

  1. Match pane.name to the recipient.
  2. Prefer matches whose env.ATM_TEAM equals the resolved team.
  3. If exactly one recipient-name match exists without a team tag, accept it as a compatibility fallback.
  4. Reject missing matches, ambiguous team matches, empty pane IDs, malformed TOML structures, and unavailable TOML support.

Errors are represented with stable codes such as file_missing, not_found, empty_pane, parse_error, ambiguous_match, and invalid_structure. This lets callers and logs distinguish configuration repair from delivery failures.

Dependencies

The script depends only on the Python standard library in Python 3.11+:

  • tomllib parses .atm.toml.
  • json parses ATM_POST_SEND and Claude config.json, and emits machine-readable diagnostics.
  • pathlib and os locate repository configuration relative to the current project context.
  • subprocess invokes tmux send-keys.
  • shlex safely renders manual recovery commands.
  • datetime timestamps append-only delivery logs at /tmp/atm-nudge.log.
  • time inserts a short delay between sending literal text and sending Enter.
  • sys supplies CLI arguments, the current interpreter, and output streams.

For Python versions before 3.11, it attempts to import tomli as a compatible TOML parser. If neither parser is available, normal-mode lookup fails with no_tomllib; direct --pane delivery remains independent of TOML parsing.

External runtime dependencies are:

  • A working tmux executable.
  • A target pane that accepts tmux send-keys.
  • A repository-local .atm.toml for normal delivery.
  • Optionally, Claude’s ~/.claude/teams/<team>/config.json for consistency checks and recovery recommendations.

The module does not depend on ATM runtime crates or application crates. Its boundary is operational tooling: environment input, filesystem configuration, tmux delivery, and JSON diagnostics.

Usage Notes

Normal post-send delivery

With .atm.toml available from the project directory or any parent directory:

scripts/atm-nudge.py grecon

The script resolves the team, finds the unique pane for grecon@<team>, generates the standard task instruction, sends it as literal tmux text, then sends Enter.

A representative authoritative pane definition is:

[[rmux.windows.panes]]
name = "grecon"
tmux_pane_id = "%4"

[rmux.windows.panes.env]
ATM_TEAM = "hermes"

If there is one pane named grecon and it lacks ATM_TEAM, the script accepts it. If multiple same-name panes exist, tag the intended pane with env.ATM_TEAM to avoid ambiguity.

Sending an explicit message

scripts/atm-nudge.py grecon "Please inspect the failing integration test."

The supplied message replaces the generated default. It must be non-empty after trimming.

Direct-pane override

scripts/atm-nudge.py --pane '%4' grecon "Please inspect the failing integration test."

Use this for controlled recovery or diagnostics when the committed mapping is unavailable. The override skips both configuration lookups, so it does not validate that the pane belongs to the requested recipient or team.

Acknowledgement messages

When ATM_POST_SEND is valid JSON with "is_ack": true, and no explicit message is supplied, build_message() generates acknowledgement-specific actions. If the payload contains a message_id, it includes that ID in the acknowledgement instruction.

Malformed ATM_POST_SEND is intentionally non-fatal and behaves as an empty payload.

Handling stale config.json

If .atm.toml resolves %4 but Claude’s local config says %7, the script:

  1. Delivers to %4, because it is authoritative.
  2. Logs the mismatch.
  3. Writes a detailed warning JSON object to stderr.
  4. Emits a compact "warn" hook result to stdout.
  5. Returns success.

Treat the warning as configuration drift that should be repaired, not as proof that delivery failed.

When delivery is blocked

If .atm.toml cannot resolve a pane, no automatic delivery occurs. The error payload includes:

  • The authoritative lookup failure.
  • The advisory config.json result.
  • A suggested pane ID from config.json, or %1 as a fallback.
  • A shell-safe nudge_command for manual delivery.
  • Targeted configuration fixes.

The suggested pane is explicitly advisory and may be stale. Verify it before executing the recovery command.

Operational pitfalls

  • Do not rely on config.json as the delivery source; it is intentionally non-authoritative.
  • Ensure recipient names match exactly.
  • Ensure tmux_pane_id is non-empty and team-scoped mappings are unique.
  • Preserve the 0.25 second delay between literal message input and Enter; removing it may make pane input less reliable.
  • tmux send-keys -l sends literal text, avoiding shell interpretation of the message content.
  • Review changes to team fallback order carefully: they alter which pane may receive a post-send notification.
  • /tmp/atm-nudge.log is operational telemetry, not durable audit storage.
