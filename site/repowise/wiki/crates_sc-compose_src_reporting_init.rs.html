Overview

This Application-layer edge connector is the reporting initialization and smoke-execution orchestrator: it consumes a workspace root, smoke fixture, variable file, archive option, and composition observer, and produces scaffold or materialized smoke-report results for command-layer callers.

init.rs connects the reporting command surface to the pure sc_composer rendering library and reporting output helpers. It has two workflows:

  • Scaffold initialization canonicalizes the requested workspace and delegates creation of the report files to write_report_scaffold.
  • Smoke reporting resolves and confines input paths, renders a file-mode composition, writes the rendered entrypoint, then materializes metadata and optional archived artifacts.

This is a hotspot for both change frequency and complexity. Changes can affect workspace-boundary enforcement, diagnostic classification, observer behavior, report artifact layouts, and JSON-facing result structures.

Public API

All exposed items are pub(crate), making them internal crate APIs rather than public library exports.

Item Purpose
ReportsInitResult Serializable result of report-scaffold initialization. Contains the canonical workspace_root and the relative created_paths returned by the scaffold writer.
ReportsSmokeResult Serializable result of a smoke report. Contains report identity, production timestamp, status, output paths, artifact lists, and non-serialized composition warnings.
init_report_scaffold(root) Canonicalizes root, writes the report scaffold, and returns its created paths.
run_smoke_report(root, fixture, vars, archive, observer) Renders a confined smoke fixture using the supplied variables, writes the smoke entrypoint, produces metadata and optional archives, and returns report details plus rendering warnings.

ReportsSmokeResult.warnings is deliberately excluded from serialization. Consumers that need machine-readable report metadata receive stable report fields and paths, while in-process callers can still inspect Diagnostic values.

write_smoke_outputs is private. It fixes the smoke report’s identity and layout:

  • report_id: smoke
  • kind: smoke
  • status: pass
  • entrypoint: SMOKE_ENTRYPOINT_RELATIVE_PATH
  • metadata: SMOKE_METADATA_RELATIVE_PATH

Dependencies

  • sc_composer supplies ComposeRequest, file composition mode, default policy, ConfiningRoot, diagnostics, and compose_with_observer. The module is an application-layer adapter over this rendering boundary.
  • reporting::scaffold owns scaffold creation and the canonical smoke output path constants.
  • reporting::path::resolve_relative_path resolves fixture and variable-file inputs against the canonical workspace.
  • reporting::output::write_report_metadata_and_archive writes report metadata, maintains latest artifacts, and optionally creates archived copies.
  • var_file::load_var_file parses the variables input for the composition request.
  • CommandError converts filesystem, configuration, and composition failures into CLI-appropriate errors and diagnostic codes.
  • serde plus path_utils provide JSON-safe serialization for filesystem paths.

The primary cross-layer caller is commands/reports/scaffold.rs, through run_reports_init. Internal reporting modules also depend on this module’s result types and workflows.

Usage Notes

Initialize a report workspace

The initialization path requires an existing root because fs::canonicalize resolves it before any scaffold files are written. A nonexistent or inaccessible root becomes a CommandError::usage_with_code carrying ErrConfigParse.

let result = init_report_scaffold(workspace_root)?;

println!("workspace: {}", result.workspace_root.display());
for path in result.created_paths {
    println!("created: {path}");
}

Treat workspace_root as canonical. Do not assume it preserves the spelling of the caller’s original path, especially when symlinks are involved.

Run a smoke report

A smoke run is a controlled file-rendering operation:

  1. Canonicalize the workspace root.
  2. Resolve fixture and vars relative to that root.
  3. Verify the resolved fixture remains below the workspace root.
  4. Build a ComposeRequest with ComposeMode::File and a ConfiningRoot.
  5. Load variables, render through the supplied observer, and write the rendered entrypoint.
  6. Materialize latest-report metadata and, when requested, archived artifacts.
let result = run_smoke_report(
    workspace_root,
    Path::new("fixtures/smoke.jinja"),
    Path::new("vars/smoke.json"),
    true,
    observer,
)?;

assert_eq!(result.report_id, "smoke");
assert_eq!(result.status, "pass");

for warning in &result.warnings {
    // Consume in-process diagnostics; they are not serialized with the result.
}

fixture must resolve under the workspace root. The implementation strips the root prefix before creating ComposeMode::File, so the composer receives a workspace-relative template path rather than an unconstrained absolute path.

The variable file is resolved through the same workspace-relative helper, but only the fixture is explicitly checked with strip_prefix in this module. Preserve this distinction when modifying path handling: changes should remain consistent with resolve_relative_path’s validation guarantees.

Rendering warnings do not fail a successful smoke report. They are retained in ReportsSmokeResult.warnings, while the materialized report is still marked pass after successful composition and output writing.

Any failure to write the rendered entrypoint is classified as a render-write error. Failures in canonicalization, confinement setup, fixture-root validation, or report-output materialization are translated to usage/configuration errors. Keep these mappings intact so CLI diagnostics remain actionable and consistently coded.
