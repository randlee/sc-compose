Overview

Reports command module is the CLI-layer edge connector that parses reports subcommands into typed arguments and re-exports their handlers for command dispatch. It is imported across the CLI boundary by cli.rs, commands::dispatch, and the reports implementation modules.

The module declares the publish, render, and scaffold command families, while centralizing their Clap argument schemas.

Public API

All exposed items are pub(crate), making them available throughout the sc-compose crate but not to external crates.

  • ReportsArgs wraps the selected ReportsSubcommand.
  • ReportsSubcommand defines:
  • Init — initialize report scaffolding.
  • Smoke — run a fixture-based smoke report.
  • Finalize — record a producer result and optional artifacts.
  • RenderSpec — render a semantic diagram specification to Mermaid.
  • Index — summarize report entrypoints and sidecars.
  • Verify — verify required catalog evidence.
  • PublishManifest — generate a machine-readable manifest.
  • Argument types:
  • ReportsInitArgs
  • ReportsSmokeArgs
  • ReportsFinalizeArgs
  • ReportsRenderSpecArgs
  • ReportsIndexArgs
  • ReportsVerifyArgs
  • ReportsPublishManifestArgs
  • ReportCatalogArgs
  • ReportRenderManyArgs
  • Re-exported handlers:
  • Scaffold: run_reports_init, run_reports_smoke, run_reports_index, run_reports_verify
  • Rendering: run_reports_render_spec, run_report_catalog, run_report_render_many
  • Publishing: run_reports_finalize, run_reports_publish_manifest

Dependencies

  • clap::{Args, Subcommand} derives the command hierarchy and long-option parsing.
  • std::path::PathBuf represents filesystem inputs such as report roots, fixtures, specifications, entrypoints, artifacts, and output directories.
  • reports::scaffold, reports::render, and reports::publish contain the corresponding command implementations.

Usage Notes

  • All command argument types accept --root, defaulting to the current directory (.).
  • --json requests machine-readable output where supported.
  • reports smoke requires --fixture and --vars; --archive controls archival output.
  • reports finalize requires --report-id, --kind, and --entrypoint; it defaults --status to pass and accepts repeated --artifact options.
  • reports render-spec requires --spec and can archive its output.
  • ReportRenderManyArgs requires --id, --glob, and --output-dir. Its --template and --template-family selectors cannot be supplied together.
  • Dispatch code consumes ReportsSubcommand and invokes the re-exported handlers, which in turn connect report operations to the reporting-layer routines such as smoke fixture execution and semantic-spec rendering.
