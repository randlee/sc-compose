File: crates/sc-composer/src/verify.rs

Overview

verify.rs is the Application-layer drift-verification adapter that renders a ComposeRequest, reads a deployed text file, compares normalized outputs, and produces a VerifyResult with an optional unified diff. It exposes a simple verification entry point and an observer-aware variant, reusing the composition pipeline rather than implementing rendering separately.

Verification treats line-ending differences (CRLF versus LF) and a final trailing newline as equivalent. When content differs, it produces a line-oriented unified diff whose left header is the deployed file path and whose right header identifies the rendered template path.

Public API

verify

pub fn verify(
    request: &ComposeRequest,
    deployed_path: impl AsRef<Path>,
) -> Result<VerifyResult, ComposeError>

Convenience entry point for callers that do not need lifecycle events. It creates a NoopObserver and delegates to verify_with_observer.

Inputs:

  • request: the template composition request, including template mode, confined root, variables, and composition policy.
  • deployed_path: the deployed output file to check.

Output:

  • Ok(VerifyResult) contains both source texts, their paths, propagated composition warnings, a clean flag, and diff: Option<String>.
  • Err(ComposeError) is returned if composition fails or the deployed file cannot be read as UTF-8 text.

verify_with_observer

pub fn verify_with_observer(
    request: &ComposeRequest,
    deployed_path: impl AsRef<Path>,
    observer: &mut dyn CompositionObserver,
) -> Result<VerifyResult, ComposeError>

Performs the same verification while emitting on_verify_start before work and on_verify_end after the attempt. The end event is emitted whether verification succeeds or fails because the core work is evaluated inside a closure before the end callback.

The resulting VerifyResult includes:

  • clean: true when normalized deployed and rendered text match.
  • resolved_template_path: the final template path resolved by composition.
  • deployed_path: an owned copy of the input path.
  • rendered_text and deployed_text: original, unnormalized text.
  • diff: a unified diff only when drift is present.
  • warnings: warnings produced during composition.

Internal helpers

read_deployed_text reads the file with fs::read_to_string and maps I/O failures into configuration-oriented ComposeError values:

  • Missing file → ErrResolveNotFound
  • Invalid UTF-8 → ErrConfigRead
  • Other read failures → ErrConfigParse

Each mapped error includes an InspectPath recovery hint for the deployed path.

render_diff normalizes both texts, short-circuits on equality, and otherwise generates a similar::TextDiff unified diff.

normalize_text_for_compare uses str::lines() and rejoins with \n. This canonicalizes CRLF and LF endings and removes the significance of a single final newline.

Dependencies

  • compose_with_observer: renders the requested template and supplies the resolved template path, rendered text, and warnings. Verification is intentionally downstream of composition.
  • CompositionObserver, VerifyStartEvent, VerifyEndEvent, and NoopObserver: support observable verification without requiring event handling from ordinary callers.
  • ComposeRequest and VerifyResult: define the verification input and result contract.
  • ComposeError, ConfigError, DiagnosticCode, and recovery hints: provide structured, actionable failures for deployed-file read problems.
  • std::fs and std::path::Path: read deployed output from the filesystem.
  • similar::TextDiff: produces human-readable, line-based unified diffs.

The module is re-exported through lib.rs, making its public entry points available to library consumers and higher-level bindings.

Usage Notes

A basic verification flow renders the requested template and compares it with an existing deployment:

use std::collections::BTreeMap;
use std::path::PathBuf;

use sc_composer::{
    verify, ComposeMode, ComposePolicy, ComposeRequest, ConfiningRoot,
};

let root = PathBuf::from("/workspace/templates");
let request = ComposeRequest {
    runtime: None,
    mode: ComposeMode::File {
        template_path: PathBuf::from("service.conf.j2"),
    },
    root: ConfiningRoot::new(&root)?,
    vars_input: BTreeMap::default(),
    vars_env: BTreeMap::default(),
    vars_defaults: BTreeMap::default(),
    guidance_block: None,
    user_prompt: None,
    policy: ComposePolicy::default(),
};

let result = verify(&request, "/etc/my-service/service.conf")?;

if result.clean {
    println!("deployment matches {}", result.resolved_template_path.display());
} else if let Some(diff) = result.diff {
    println!("deployment drift detected:\n{diff}");
}

Use verify_with_observer when progress reporting, telemetry, or UI integration needs verification lifecycle callbacks:

let result = verify_with_observer(&request, deployed_path, &mut observer)?;

The observer receives exactly one start and one end event for a verification attempt, including attempts that fail while rendering or reading the deployed file. Observer implementations should therefore treat the end event as completion, not as proof of success.

Comparison normalization is deliberately narrow:

  • CRLF and LF line endings compare as equal.
  • A trailing newline difference compares as equal.
  • Whitespace within lines remains significant.
  • Blank-line placement remains significant.
  • The VerifyResult preserves original text, so consumers needing byte- or newline-sensitive analysis must inspect deployed_text and rendered_text directly rather than relying only on clean.

A missing deployed file is reported as a not-found resolution diagnostic, while a non-UTF-8 deployed file is rejected rather than compared as bytes. This module is therefore suitable for text-template deployments, not arbitrary binary artifacts.

Multi-pass rendering behavior is inherited from compose_with_observer. Verification compares the final rendered output, including correctly resolved multi-pass template values, rather than attempting a separate expansion path that could diverge from normal composition behavior.
