FUZZ-018

Minimal template / frontmatter
main.formula.toml.j2: formula = "inc" / version = 1 / type = "workflow" / @<frag/common.toml.j2> / [[steps]] id = "local" ...; frag/common.toml.j2: [[steps]] id = "shared" title = "Shared step"
Input
render request, compose_variables {}
Expected
help bead 'Shared step blocks': include fragments with sc-compose's @<path> include syntax; FR-23.1 (structure from loops, conditionals, includes); FR-3.
Observed
Exit 0 but the rendered formula keeps the literal line '@<frag/common.toml.j2>'; the same text through plain `sc-compose render` expands the include. A later preview-attach fails with BEADS_COOK_FAILED. Reproduced 3/3 by the coordinator; origin/develop renders the same.
Requirement / ADR
FR-23.1, FR-3, bead manual 'Shared step blocks', ADR-0023 step_construct guidance
Requirement / ADR follow-up
No new ADR needed.
Root cause
render_formula calls Renderer::render_named on the raw template text and bypasses sc-composer's include-expansion pipeline.
Recommended fix
Run include expansion (confined to working_directory) before rendering bead templates.
