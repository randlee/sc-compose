FUZZ-050

Minimal template / frontmatter
wf/rel.formula.toml.j2: steps build, verify (needs build)
Input
attach request (pour_authorization CreatePersistentBeads, existing parent, ref pdN) with a DIRECTORY at <rendered_formula>.graph.json
Expected
Refuse before any write (run 2 refused this before bd create), or, if bd committed, report the committed apply. ADR-0023: 'A failure of either command is GraphApplyFailed; bd has written nothing'.
Observed
Exit 2, outcome failed, attach stage BEADS_RENDER_FAILED 'formula rendering failed: Is a directory (os error 21)', no graph ids reported, but bd now holds the beads <P>.pdN-build and <P>.pdN-verify. preview-attach gives the same misleading code without writing.
Requirement / ADR
ADR-0023 Stages/apply paragraph; Authorization and confinement
Requirement / ADR follow-up
No new ADR needed.
Root cause
PendingCreate::execute runs bd create --graph on a request-owned snapshot and only then publishes the plan to <rendered_formula>.graph.json; a publish error discards the successful apply and is mapped to RenderFailed.
Recommended fix
Check/publish the plan path before invoking bd create --graph (or report the committed ids with a publish-failure code).

FUZZ-051

Minimal template / frontmatter
{"a":[1, 2]}
Input
destination absent
Expected
render.md 'Appending JSON records' step 3: 'writes it as one compact UTF-8 line (embedded newlines stay escaped) followed by \n'.
Observed
Exit 0; nl.jsonl holds 2 physical lines '{"a":[1,' and '2]}', neither valid JSON. Nested whitespace is kept ({"z":[1, 2]}); only the top level is compacted. The concurrent-append family did not hit this because its records keep nested values on one line.
Requirement / ADR
render.md steps 2-3; FR-7 render --append (JSON Lines)
Requirement / ADR follow-up
No new ADR needed.
Root cause
append_json_record re-serializes a BTreeMap<String, Box<RawValue>>, so each top-level value's raw text (including newlines and spaces) is written verbatim.
Recommended fix
Re-serialize nested values compactly while preserving number lexemes (e.g. serde_json arbitrary_precision Value), or minify RawValue text outside strings.
