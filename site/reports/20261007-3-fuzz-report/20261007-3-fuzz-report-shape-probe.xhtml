FUZZ-049

Minimal template / frontmatter
wf/a.formula.toml.j2: formula = "a" / version = 1 / type = "workflow" / [[steps]] id = "s" title = "A {{{ v }}}"; wf/b.formula.toml.j2 identical with title "B {{{ v }}}"
Input
render request with "template":"wf/a.formula.toml.j2" and a second, later "template":"wf/b.formula.toml.j2" (also: formula_name of type object)
Expected
Exit 3 BEADS_REQUEST_DESERIALIZATION_FAILED as on baseline 080f261 ('duplicate field `template`') and at d47d35e (run-2 f1r 70/70 passed). ADR-0023 Decision 1: Phase R requests parse unchanged.
Observed
Exit 0, rendered title "B 1" (last duplicate wins); wrong-type formula_name accepted. Any duplicate top-level key on a render request is accepted. Shape 13 cases.
Requirement / ADR
ADR-0023 Decision 1; help bead Request errors (exit 3); FR-7
Requirement / ADR follow-up
No new ADR needed.
Root cause
parse_request: when the typed parse of a render request fails, it re-parses into serde_json::Value (duplicates collapse, last wins), drops formula_name and retries, swallowing every typed failure the Value round-trip hides.
Recommended fix
Retry only for a FormulaName grammar failure, on the original text (e.g. a raw-string formula_name), never via a Value round-trip.

Observed

Requirement / ADR

Requirement / ADR follow-up

Root cause
